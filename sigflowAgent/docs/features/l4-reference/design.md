# L4 参考解首版设计

本增量的需求、接口、任务与验证入口统一见 [L4 文档索引](README.md)。

适用基线为 `60f3b4c`。本文件定义开发试点和发布条件。现有内部约束见[参考动作与恢复](../../history/stages/stage-21-reference-host.md)和[审阅材料与正文读取](../../history/stages/stage-30-reference-body.md)，界面交互沿用 [GUI 规格](../../../../docs/agent/SigFlow-Edu-Agent-GUI-Spec.md)。

## 1. 学生何时可以查看

L4 是当前题目的参考解查看动作。现有 L4 按钮改作「查看参考解」入口，保留 L1–L3 的等级选择语义。入口在以下条件同时满足时可用：

- 正式宿主启用了原生参考解通道，权限策略允许当前范围查看。
- 当前运行是 L3、`WaitingStudent`，工程、修订、快照、证据与界面当前绑定一致。
- 当前运行没有待处理动作或活动验证计划，既有教学动作预算仍可使用。
- 材料提供器可以为当前工程、修订、问题和策略找到一份有效的审阅材料。

首次点击提交 `reference_request`。U2 校验上述条件并原子提交挑战。界面展示题目、适用修订以及「确认后将直接显示参考解要点」，并提供独立的确认和返回操作。挑战沿用现有 **300 秒**有效期，以宿主时间判定。第二次点击才申请凭据。按 Enter 触发提问、打开 Agent、普通聊天指令和「下一提示」均走自己的原路径。

退出确认框只关闭当前确认界面。未提交确认的挑战随过期、其他教学动作、工程修订变动或取消失效。重新申请可替换仍处于可替换阶段的挑战。已有核销不确定记录时，引导恢复原操作。

## 2. 试点题目与正文

| 项目 | 首版决定 |
| --- | --- |
| 工程样例 | `examples/full_adder` 的隔离副本 |
| 问题 | 全加器进位只计算 `a & b`，遗漏 `cin` |
| 建议试点标识 | `full-adder-carry-cin`。由试点配置与宿主实际绑定对应，客户端不能以请求指定该映射。 |
| 适用版本 | 一个包含上述错误、可通过仿真复现的已保存修订。以 Gateway 真实工程 ID 和修订为准，受控夹具记录源码及报告摘要。 |
| 可观察证据 | 在 `a=0, b=1, cin=1` 时观察到 `cout=0`，预期 `sum=0, cout=1`。 |
| 参考材料 | 解释遗漏进位的原因，给出 `(a & b) \| (a & cin) \| (b & cin)` 的逻辑表达式，并要求检查全部 8 组输入的 `sum`、`cout`。 |

开发夹具使用本机隔离工作目录和标记为「合成测试材料」的清单。生产材料使用已有 `ReviewedMaterialProvider` 的固定 manifest 摘要、正文摘要、项目/修订/问题/策略匹配及有效期校验。每份材料至少两位不同审阅者。可信审阅校验负责确认身份、审阅范围和撤销状态。材料目录与固定摘要由可信启动配置提供。首版正文为有界 UTF-8 纯文本，沿用现有 32 KiB 限制，展示题目、版本、错误机制、修正要点和验证步骤。

## 3. 签发、核销与正文交付

普通教学入口维持当前 L1–L3 行为。新增原生专用通道时，由可信启动组合显式启用。C++ 启动控制器为每个 sidecar 进程生成独立的原生 L4 通道令牌，通过启动管道交付，仅用于专用路由的单值头 `X-SigFlow-Reference-UI`。它和普通认证、学习者归属及当前 Gateway 工程证据检查共同生效。通道令牌加入已有的敏感信息脱敏配置。当前本机 learner 仍以可信 UI 断言为准。跨用户登录授权另行设计。

建议把专用操作放在 `/api/v1/u2/runs/{run_id}/reference` 下，使用独立 DTO。外部路径中的 run ID 由正式宿主解析为 U2 内部绑定。

| 操作 | 请求 | 成功返回 |
| --- | --- | --- |
| 读取入口状态 | `GET /reference` | `unavailable`、`eligible`、`awaiting_confirmation`、`pending`、`confirmed` 或 `reconciliation_required`，及当前状态版本和必要提示。确认前仅在专用接口交付挑战和签发所需字段。 |
| 申请查看 | `POST /reference/request`，带请求动作 ID 和预期状态版本 | 已受理状态。界面读取 U2 提交后的挑战。 |
| 确认查看 | `POST /reference/confirm`，带挑战 ID、挑战指定的确认动作 ID、挑战版本和 Gateway 凭据 ID | 已受理状态。核销成功后可通过专用状态读取确认结果。 |
| 读取正文 | `POST /reference/body`，带已确认的当前状态版本 | 只读返回材料标识、摘要、策略、适用修订和正文。响应为 `Cache-Control: no-store`，读取不消耗教学动作预算或再次核销。 |
| 显式恢复 | `POST /reference/reconcile`，带恢复动作 ID 和恢复后的当前状态版本 | 已受理状态。宿主从私有日志读取原挑战、原凭据和原审批版本。 |

所有版本作为十进制字符串传输。动作使用已有幂等规则，相同 ID 和参数可以安全重查结果。API 版本和客户端能力单独声明为原生参考解试点。普通 `/runs`、通用 `/actions` 和既有 `http_l4_available` 继续保持原行为。

1. **C++ 原生控制器**在第二次点击时核对当前界面绑定及挑战有效期，仅以 Gateway UI 身份调用 `POST /api/v1/projects/{project_id}/ui-receipts`。签发字段使用挑战中的 **U2 内部 session ID**、问题、修订、策略、挑战 ID、确认动作 ID、挑战状态版本和 `level=l4`。凭据有效期至多 60 秒，签发时裁到挑战剩余有效期。Gateway UI 签发身份留在 C++。
2. **正式宿主与 U2**先按外部运行和学习者解析可信绑定，再复查当前修订与证据。复用 `ReferenceActions` 与 `GatewayReceiptClient`，核对挑战和凭据作用域。题目由已匹配的挑战绑定，沿用 Gateway 凭据查询隐藏题目字段的约定。核销采用 U2 内部 run ID 和原确认动作 ID。核销结果进入私有 `ReferenceJournal`。常规状态、事件和教学记忆仅保存必要的材料标识及授权结果。
3. **专用正文入口**复用 `Runtime.reference_body`。读取前后校验当前绑定、状态版本及材料审阅状态。GUI 接收时再次核对当前展示运行及修订，正文仅存在于当前会话的只读参考解卡。切换工程、修订或运行，取消或关闭会话时立即清除卡片。卡片可见时沿用后台刷新，每 5 秒查询专用状态以检测撤销，查询只返回授权状态；失效或无法确认授权时清除卡片。正文、凭据和审阅者内部标识不进入普通对话、检索、模型输入、诊断日志或学习记录。

## 4. 失败、重试与恢复

| 场景 | 首版行为与验收 |
| --- | --- |
| 正常路径 | 仿真复现缺进位，正式宿主推进到 L3。第一次申请只返回挑战。第二次独立点击完成一次签发和一次核销。正文卡显示预期内容。 |
| 直接请求或伪造 | 普通 HTTP L4、仅持有普通教学 bearer、伪造凭据、错误 learner、其他工程或运行的凭据全部拒绝。正文读取前置校验失败时不读取材料正文。 |
| 挑战或凭据过期 | 提示「查看授权已过期」。未进入核销的操作可以重新申请。确认前保存出新版本时清除旧挑战，重新绑定新版本后再申请。 |
| 重复点击或响应丢失 | 请求在途禁用重复点击。遇到确认结果不明时先读参考状态。若原凭据已签发且同一次操作仍在当前进程中，可用原挑战、原凭据和原动作 ID 恢复提交。其他动作使用同一凭据拒绝。 |
| 核销尚未确认时 sidecar 退出 | 同一 Gateway 实例内，工作台进入现有恢复流程，重新校验工程和证据。学生显式触发 `reference_reconcile`，使用原凭据、原核销动作和原审批版本。已核销的结果以幂等方式核对。若凭据仍未核销且授权已过期，结果拒绝。 |
| 核销完成后退出 | 同一实例恢复前关闭正文。恢复并重核成功后，按当前版本重新读取。原挑战仅创建但未开始核销时，重启后重新申请。整个 IDE 重启产生新 Gateway 实例时，旧挑战和凭据作废，学生在新运行中重新申请。 |
| 撤销或材料更换 | 在申请后、核销后和读取过程中分别模拟撤销。服务拒绝继续投递，已展示的卡片在收到当前参考状态失效后清除。 |
| 传输异常 | 若尚未签发或尚未开始核销，显示可重试原因。若存在核销不确定记录，保留原操作并引导恢复。 |

验收包含正文不进入 SQLite 常规状态、事件、日志或学习记录的检查。还需验证从申请到阅读没有额外模型调用，也不提交 EDA Job。

## 实施顺序与分工

1. **U2 试点材料和内部链路。** 建立确定性的隔离全加器夹具，记录工程与证据绑定。先通过真实 Runtime、受审材料提供器和 Gateway 凭据核销验证内部成功路径与拒绝路径。开发材料对正式环境保持不可用。
2. **U2 与 U1 宿主接入。** 在 `teaching_factory.py`、`teaching.py` 和 `teaching_routes.py` 增加显式装配及专用契约。覆盖独立原生凭据、外部运行到内部挑战的映射、当前修订校验、过期和崩溃恢复。同步契约和变更记录。
3. **S3 与 U2 原生接线。** 在现有 L4 位置接查看动作，增加可信签发客户端，复用现有卡片与滚动区。验收两次独立操作、状态清理、结果迟到丢弃和窄窗口下的完整阅读。
4. **试点开放。** 接入正式审阅身份和撤销来源，登记真实材料。以一个受控工程完成原生联合验收后，由可信配置精确开启覆盖范围。
