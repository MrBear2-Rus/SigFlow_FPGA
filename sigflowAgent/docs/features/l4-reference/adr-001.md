# ADR 001 原生参考解通道与实例边界

状态为设计提案，宿主接口和启动凭据待 U1、U2、S3 联调验证。适用 L4 首版。

## 背景

正式 U2 宿主目前只发布 L1–L3 常规教学状态。参考解底层已经具备内部门禁、可信材料校验及核销日志。学生查看答案需要同时证明明确操作、范围匹配和有效材料。普通教学对话具备自己的认证，但其语义允许提示、刷新和重放，生命周期和参考正文不同。

## 选择及理由

| 方案 | 对首版的影响 |
| --- | --- |
| 扩展通用 `/actions` 和常规状态以返回参考解 | 可复用现有轮询，涉及普通教学契约、状态持久化和重放投影，正文边界较难审查。 |
| 新增正式宿主内的原生专用路由 | 复用现有宿主和运行绑定。专用授权、审计及测试有独立落点。新增原生启动凭据和请求类型。 |
| 新建参考解服务进程 | 可独立部署。需要额外生命周期、端口与实例恢复协调，首版工程成本较高。 |

采用同一宿主内的专用路由。C++ 通过现有 Gateway UI 身份签发教学凭据，U2 通过现有 Agent 端口核验和核销。专用通道身份独立于普通 UI bearer。会话归属沿用本机可信 UI，材料审阅身份由可信校验方提供。正文只由专用读取产生，核销结果由已有 `ReferenceJournal` 持久化。

同一 Gateway 实例内可对不明确的核销结果进行重核。新实例重新走申请和确认。旧实例的凭据、核销结果和正文均属于原实例。现有 Gateway 签发接口尚无可供 L4 使用的签发幂等键。签发响应不明确且客户端没有凭据 ID 时，本轮保持等待，挑战过期后允许学生重申。确认、核销与重核继续复用各自稳定的动作键。

实现成本集中于启动装配、专用协议和原生控制器。关闭可信配置即可停止新授权和正文读取。后续具备独立用户认证或跨实例授权需求时，另立决策记录，保留此版本的验收和兼容边界。[接口契约](contract.md)
