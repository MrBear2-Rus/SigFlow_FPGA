## L4-T01 制作确定性的试点夹具

实施入口为 `examples/full_adder` 及 `sigflowAgent/tests/fixtures/l4_full_adder/`。后者为拟新增夹具位置。

- [ ] 从全加器样例复制隔离工程，在副本的 RTL 加入 `cout=a & b` 缺陷，保留正常样例。
- [ ] 使用真实仿真 Job 记录输入 `011` 的预期及观察输出、真实工程 ID、修订、快照、Job ID、源码摘要与产物摘要。材料绑定由可信夹具装配从结果取得。
- [ ] 编写标记为合成的参考正文。用正确表达式在另一隔离修订验证 8 组输入，记录每组预期及结果。

完成条件是另一位开发者用同样步骤能复现错误和修正结果，且合成材料默认无法从生产启动配置加载。

## L4-T02 装配现有 U2 参考组件

主要入口为 `host/materials.py`、`host/reference_actions.py`、`host/runtime.py` 和 `clients/receipts.py`。均位于 `sigflowAgent/sigflow_teaching_core/`。

- [ ] 扩展既有材料和参考动作测试，先运行一个未确认而读取正文的负例，以及一个核销成功但响应丢失的场景。
- [ ] 通过可信夹具显式组合 `ReviewedMaterialProvider`、`GatewayReceiptClient` 和现有 Runtime。测试从当前真实证据推进到 L3、申请、核销及内部读取。
- [ ] 增加版本切换、过期、撤销和重核验证。使用可控时钟或注入故障点，记录真实核销次数及当前状态。

完成条件是内部正例可取正文，负例无正文也无额外核销。此批可由 U2 独立交付。

## L4-T03 实现正式宿主专用通道

主要入口为 `agent/src/sigflow_edu_agent/teaching_factory.py`、`teaching.py`、`teaching_routes.py`、`bootstrap.py`，以及 U2 的 `host/shared_adapter.py`。

- [ ] 将 [契约](contract.md) 变成请求和响应的可机器校验 schema 与 HTTP 测试。先执行默认关闭、缺头拒绝、普通动作拒绝等测试。
- [ ] 装配可信开关和独立原生凭据，增加状态、申请、确认、正文和恢复路由。作用域从已有当前版本及对外运行归属映射到内部绑定。
- [ ] 对照现有材料和日志边界测试敏感字段脱敏，模拟读取期间保存新修订或撤销材料。同步 `contracts/edu-agent/v1/CHANGELOG.md`。

完成条件是同一正式 HTTP 宿主能在受控配置及完整认证下交付正文，原 L1–L3、无配置启动和普通 L4 拒绝均保持兼容。

## L4-T04 接通 Windows 原生界面

以 `main/agent/gui/AgentNavigation.cpp` 的既有 L4 入口为起点，接入 `main/agent/AgentApiClient.cpp`、启动控制器和可信 Gateway UI 客户端。复用现有卡片样式和滚动容器。

- [ ] 按专用状态启用入口，显示第一次申请后的挑战与独立确认。模拟只打开界面、提交问题、回车与重复点击，统计签发次数。
- [ ] 用已核对的挑战字段签发一次性凭据。等待 U2 确认，按提交后的状态版本读取正文。正常教学轮询保留原节奏。参考卡可见时每 5 秒检查一次授权状态。
- [ ] 将正文渲染为当前运行的只读卡片。测试切换项目、保存修订、取消和迟到响应。以至少一种窄窗形态检验全文滚动和焦点恢复。

完成条件是只有两次明确操作才会展示参考解，界面在绑定变化时及时移除卡片。
