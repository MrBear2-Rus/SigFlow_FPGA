# U2 教学证据时间线

时间线展示单次教学运行已提交的事实。原生工作台在「教学辅助内容 → 证据链」现有分区内显示最近记录。

1. 在 DurableStore 原有事件事务中把白名单事实写入同一个 SQLite 库的 `event_timeline` 表。记录修订、快照、基线 Job、证据 ID、动作阶段和可确认的复测进度。新增表保留原有事件表结构。旧记录的详情为空，事实随其对应事件淘汰。
2. 在正式宿主提供 `GET /api/v1/u2/runs/{run_id}/timeline`，复用身份、运行归属和现有事件保留窗口。省略 `after` 时读取最近一页，指定 `after` 时按序号续读。保留窗口之前的游标返回 410，客户端可重新读取最近一页。原有 `/events` 响应形状保持兼容。
3. 原生客户端在现有教学状态读取线程中附带读取最近 12 条。投影只展示同一运行且不晚于本次状态版本的事件。在证据链正文追加只读摘要，使用现有滚动和证据定位机制。

正式接口返回 `u2.teaching-timeline.v1`，含 `session_id`、`run_id`、`events`、`high_watermark` 和 `older_records_omitted`。事件的 `sequence` 和 `state_version` 都是十进制字符串。事件按序号升序排列，分页以最后一条返回的 `sequence` 续读。旧事件的 `fact` 为 null，其他事件包含修订、快照和基线 Job。提示和复测事件附带对应的提示等级、证据 ID 或复测 Job 及工具状态。

`execute_plan` 的 `staged` 记录表示 U2 已通过当次授权检查，并在调用工具前提交恢复点。复测证据就绪要求新的终态工具结果和有效证据。运行完成本身不代表工程验证通过。时间线不保存问题、提示正文、原始日志、令牌或审批凭证。证据定位以当前仍可解析且绑定一致的引用为准。

现有运行绑定固定的工程修订。保存修改并创建新运行后，GUI 展示新运行的记录。旧运行仍可通过已授权的只读接口查询，证据不会被替换成当前修订。当前工作台尚未安装可信的来源定位回调，因此定位按钮沿用现有禁用状态。

回归覆盖状态版本与历史修订、老数据库、重启、读取授权、分页和重复动作。GUI 验收从当前报告开始教学，生成提示并结束，再确认切换工程或运行时不会混入旧记录。
