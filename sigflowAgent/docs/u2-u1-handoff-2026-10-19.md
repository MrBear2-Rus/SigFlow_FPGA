# U2 对 U1 的剩余依赖交接

日期：2026-10-19。依据当前工作区，不评价 U1 尚未合入的分支进度。

U2 基础教学闭环已可独立开发联调：u2.host.v1 有持久化、幂等、预算、取消与恢复，已连接当前工程真实报告。U1 剩余依赖集中于统一服务及发布收口。

| 优先级 | U1 牵头交付 | 对 U2 的影响 | 联合验收 |
| --- | --- | --- | --- |
| 1 | 正式入口与共享 Agent API 统一适配 | 明确 agent/sigflowAgent 发布入口；标准 session/run/action/state 承载现有 U2 动作 | 同一工程/learner 通过共同契约完成逐层提示、验证审批、取消、恢复；DTO、错误、版本、事件共同冻结 |
| 2 | 统一服务的持久状态与生命周期 | 将 U2 SQLite/执行账本纳入正式入口，明确归档、容量回收、升级与迁移 | 重启不重跑、不继承旧审批；长期使用不依赖手工删库 |
| 3 | 安装、升级及目标平台验证 | 统一解释器、包名、启动器、协议和依赖交付 | 原生 Windows/Linux 及实际麒麟目标的安装、启动、恢复、回滚记录分别归档 |

U1 基线当前记录 agent 为内存 session/run/event；当前实现未找到 hint_next、execute_plan 和 E0–E7 恢复入口。U2 扩展已补齐开发能力，因此这些缺口主要阻碍统一产品交付，不阻止当前浮窗和真实工具测试。

L4 还需要 U3/教师材料、S1/S3 的可信身份和双确认/正文呈现；学习历史需要 U3 实际适配器；检测事实和动态激励主要依赖 S2。不能全部归为 U1 阻塞。

U2 自身仍负责真实模型重复语义评测、教师整改及参与主界面/共同接口签收，不能转记为 U1 任务。总体矩阵见 [u2-dependency-audit.md](u2-dependency-audit.md)。
