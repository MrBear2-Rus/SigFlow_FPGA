# 阶段 14：只读教学检查点与恢复

日期：2026-10-14。对应 UA-05 的会话状态及 UA-06 的重复升级防护。
实施沿用已批准的持续开发范围，不提交、不推送。

## 设计与选择

采用纯 JSON 检查点与恢复适配器，位于 `runtime/checkpoint.py`。
相比另建 HTTP/数据库，该接口可交给 U1 的事务存储接入；相比复制整个 Python
对象，严格字段校验不持久化 Provider、凭据、问题正文或证据/源码正文。
检查点仅接受无 plan、无执行记录的 explain/diagnose 会话在 WaitingStudent 或
Completed 的发布边界；执行中、失败和缺证据状态不冒充已恢复。

检查点绑定实例、session、learner、project、issue、revision、snapshot、Job、
diagnostic、policy、请求摘要、schema/workflow/policy 版本。保留 run ID、等级、
预算、版本、已接受动作及检查后的卡片。证据只存摘要。
卡片正文属于教学记录；宿主负责访问控制、保留期和删除策略。摘要不构成签名。

恢复时重新注入宿主认证的 binding、原请求、只读证据源和可选 Provider，进入
RecoveryRequired，隔离旧卡片、禁止推进及教学动作，允许宿主安全取消。
显式 reconcile 重新取证并核对
完整摘要、Job/snapshot 后才恢复暂停状态，递增版本，使旧 UI 版本失效。
提示、刷新取证和结束等已提交 action_id 保持幂等，新的 hint_next 仍最多升一级。
取证失败不调用模型，
不发布旧卡片、不执行 EDA、不恢复 grant 或 L4 权限。

宿主必须事务提交动作和检查点，并在调用模型前持久化预算预留。
本阶段不提供数据库事务、处理中请求恢复、跨进程锁或全服务崩溃一致性。
不修改 `agent/`、共享协议或 U3 数据库。
