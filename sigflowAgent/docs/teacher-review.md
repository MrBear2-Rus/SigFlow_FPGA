## 评审记录

每份记录包含匿名场景 ID、评审者 ID、评审日期、盲评批次、代码版本、
策略版本、提示模板版本、模型 ID、模型参数、课程索引版本与证据来源。
输入材料包括设计目标、所需局部 RTL、经核对的报告或波形引用、提示级别、
发布卡片和局限说明。不得将学生身份、API Key 或无关工程源码加入评审包。

## 评分维度

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 正确性 | 硬件概念错误或把合法设计当错误 | 基本正确但缺条件或有误导歧义 | 事实与证据一致，必要前提明确 |
| 递进 | 越级泄露答案或各级无区别 | 有递进但跨度过大或重复 | L1 方向、L2 范围、L3 线索逐步展开 |
| 可操作性 | 学生无法确定下一步观察 | 有行动建议但定位不充分 | 下一步具体可执行且仍由学生思考 |
| 证据 | 虚构引用、旧版本混用或过度断言 | 有引用但局限说明不足 | 可追溯引用、范围明确、缺证据时保留判断 |

每位评审者每场景总分为四项之和，范围 0–8。至少两位熟悉数字电路的
独立评审者盲评；保留原始分项评分和分歧，不用模型自评分代替。
目标为均分至少 6/8；严重硬件错误、答案越级或伪造证据仍须单独整改，
不能被平均分抵消。

## 必填结论字段

| 字段 | 内容要求 |
|---|---|
| scenario_id / reviewer_id | 可追踪的匿名标识 |
| correctness / progression / actionability / evidence | 各 0、1 或 2 |
| severe_issue | 无 / 硬件错误 / 答案泄露 / 证据伪造 / 其他严重问题 |
| observation | 指明卡片中有问题的结论及对应证据，不记录个人信息 |
| remediation | 可验证的修复要求 |
| retest | 修复版本、受影响场景和复评结论 |

## 真实模型批次

每个冻结场景至少重复 3 次，保留每次模型标识、参数、候选是否拒绝、
是否规则降级及最终发布结果。若服务不提供精确模型版本或 token 统计，
记录 unavailable，不推测。分别报告每次结果与波动，不以最佳一次代替批次。

## 发布限制

开发合成用例通过只支持确定性结构和权限行为结论；不能据此宣称
真实 detector 覆盖、真实模型安全、学生学习效果或 UA-AC08 已验收。
