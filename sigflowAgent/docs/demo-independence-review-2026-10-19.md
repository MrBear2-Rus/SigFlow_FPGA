## 需要收敛的耦合

### 1. 默认构建与运行行为

`demo/CMakeLists.txt` 将 `SIGFLOW_BUILD_AGENT_GUI_DEMO` 默认设为 ON，并把 HostClient 和浮窗源文件加入 sigflow。独立启动器虽然 EXCLUDE_FROM_ALL，主程序中的 demo 代码仍默认编译、链接。

MainFrame 在 EDU_AGENT 与 demo 均启用、且未指定自定义启动器时，自动选择 demo/u2_host.py 作为宿主。此行为发生在主窗初始化阶段，早于点击 Agent；会引入 Python 子进程及宿主初始化，而不只是多出一个标签按钮。显式配置的自定义启动器仍保留优先级。

建议：团队常规构建默认关闭 demo，由本地开发配置显式启用；演示构建保持 ON。宿主启动策略应由正式服务配置控制，或在首次打开 Agent 时启动，并保留其他宿主消费者需要预启动的场景。不要简单将整个共享 AgentServiceController 改为懒启动。

### 2. 源码与分发路径

AgentDemoWindow 使用编译期源码目录、bridge.py 的存在性及相邻 .venv 定位运行环境。独立 exe 还依赖主仓库的 UiTheme 实现；正式模式依赖 sigflowAgent 下完整的 U2 Python 包。

因此独立 exe 只表示可以单独运行 fixture 窗口，不表示复制单个 exe 就能部署，也不表示 demo 目录可以直接复制到别的项目。开发演示可接受，安装包发布需明确资源布局和 Python 服务入口。

建议：保留现有开发路径，发布时增加明确的安装资源目录配置；不为当前 demo 提前打包完整 Python 运行时。

### 3. 私有宿主协议

HostClient 检查 `u2.host.v1`，按固定教学路由与字段工作；还复制了宿主根据 instance/idempotency-key 派生 session ID 的算法，用于响应丢失时保留取消目标。这有实际恢复用途，但属于协议层耦合，算法变化需要同步修改客户端。

客户端同时承担报告筛选、创建快照、grant、启动综合、轮询、撤销和教学会话动作，职责已经超过简单聊天界面。该实现未改 Core，但会随 Gateway/宿主契约变化而调整。学生 ID 目前固定为 local-student，仅适用于本机单学生 demo。

建议：后续将连接和客户端接口稳定为小型集成层，让浮窗依赖接口；把会话恢复标识明确纳入双方协议或预先声明的客户端请求标识。不要为了这次演示提前修改 U1 共享协议或 U3 学生画像接口。

### 4. 通用修复与演示提交混杂

背景绘制和 wx 版本兼容修复会影响所有主界面用户，且不会随 demo 开关关闭。修复本身有明确用途，不应为追求隔离直接撤销。

建议：后续分别提交通用 GUI 修复、可选 demo 入口、正式 U2 对接及业务阶段改动，使评审、回退和责任归属清晰。通用 GUI 修复交由 GUI 维护者审阅。
