## 3. 各方面做了什么

**接入 Yosys（综合）**
从裸调进程演进为完整的综合任务链：Job 状态机（取消/重试/超时）、运行时预检、受控脚本生成、异步进程执行与双流日志采集、日志解析与结构化报告（LUT/DFF/BSRAM 资源统计）、GUI 任务面板。每次综合的输入/脚本/日志/网表/状态全部落盘到独立运行目录，可保存、可回溯、可重试。

**接入 nextpnr（布局布线）**
与 Yosys 对等的任务域：工具自动发现、参数注入目标器件、CST 约束校验与自动注入、fmax/关键路径/资源占用报告、独立 Job 状态机。综合与布线通过成功任务的权威产物关联，不再依赖"目录里碰巧存在的同名文件"。

**打包与上板**
仓库捆绑全部工具链运行时（Yosys / nextpnr / Apicula / openFPGALoader），用户零安装。gowin_pack 生成 `.fs` 位流并对输入/输出做 SHA-256 记账，openFPGALoader 烧录 Tang Nano 9K。示例工程已在实板跑通综合→布线→打包→烧录→采集全链路。

**架构设计：Job 化框架**
接入过程中沉淀出一套可复制的治理模式——每个外部工具都封装为「Job（状态机+独立目录+manifest）+ Runtime（预检）+ Executor（异步进程）+ 参数构建器 + LogParser/Report（结构化报告）+ GUI 面板」的统一骨架。这套骨架被 TraceBridge 直接复用，也是后续 AI 接入（生成 Job 参数、解读报告）的基础。

**TraceBridge 调试平台（本阶段最大增量）**
针对传统厂商 ILA 不跨厂商、与 IDE 割裂、只能人肉比对波形的痛点，自建软硬件联合调试闭环：

- **设计侧**：不可变调试契约 + 影子构建（原 RTL 零修改、SHA-256 校验）+ 综合后网表探针存活校验（探针被优化掉则阻断下载）+ 构建指纹（位流与波形保证同源）；
- **硬件侧**：三个自研 RTL 核——环形采样 ILA（五类触发模式）、COBS+CRC-16 调试协议核、UART 物理层，全部通过 Yosys/nextpnr/实板验证；
- **主机侧**：十阶段采集编排（指纹比对→配置→布防→分块回读→生成 VCD）、仿真与硬件波形双轨同屏自动对齐、首差异高亮、根因候选图（双击跳回 RTL/结构树/画布）、输入重放（用实采激励重跑 Verilator，区分设计 bug 与激励不一致）；
- **质量保障**：无硬件 CI 用命名管道 + 行为模型做全协议闭环回归，另有实板验收记录。
