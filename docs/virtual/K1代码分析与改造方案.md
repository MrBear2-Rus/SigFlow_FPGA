# K1 CST真实位索引与Bank电气底座：代码分析与改造方案

日期：2026-11-13｜本文为实施前的历史分析。**生产改造已完成，当前 G1/A2/A3 状态见 [K1生产改造与实测报告](K1生产改造与实测报告.md) 和 `evidence/K1-implementation-summary.json`；下文旧缺陷与未实施描述保留为当时记录。**

唯一设计契约仍为工作区v1.1主规划和《GUI评审修订与最小闭环》§2/3/7。本文不更改暂停策略、STATE规则或Web范围；将K1从字段方案落实到文件、来源适配、迁移和真正C++测试计划。

## 1. 本轮取得的可复核证据

本轮用独立CMake目标编译并直接调用未修改的`ConstraintSheet.cpp`，输入为权威`port-index-cases.json`的参考向量；结果见[evidence/K1-analysis.json](evidence/K1-analysis.json)。这项探针刻意展示旧行为，不能统计成“K1单元测试100%通过”。

| 声明/操作 | 真实旧代码结果 | 根因 |
|---|---|---|
| scalar led | 输出`led` | 此例正确，但类型里无法与[0:0]区分 |
| [0:0] / [3:0]的0位 | 输出`led`，丢`[0]` | `CstGenerator::Generate`仅在bitIndex>0时加下标 |
| [7:4]的4位 | 生成引用可写4，但Validate报4超出width=4 | 把HDL索引误当0基slot |
| [4:7]的7位 | Validate报7超出width=4 | offset/upto已被ParsePorts丢弃 |
| [0:-2]的-2位 | 校验拒绝负数，生成器省略索引 | hdl_index缺合法范围语义 |
| 未知的一位声明 | 旧接口只有width=1，仍按成功解析 | 缺少shape=unknown以及fail-closed诊断 |

向量只绑定一个bit的探针还会产生“未完整绑定”错误，这是刻意的小输入，不将它误算为额外bug；报告保留完整诊断，关注索引越界和生成格式两类问题。

同时对`tests/virtual/k1/ports.sv`运行实际工具：

| 工具 | 实际能力/结果 | 对实现的决定 |
|---|---|---|
| Yosys 0.67+（30fe16c7f） | ports中有bits/offset/upto；one_bit_vector在netnames属性中带single_bit_vector=1 | 可以作为明确声明证据之一，不能认为所有历史Yosys版本都输出该属性 |
| 本项目Verilator二进制 | `--xml-only`被拒绝，`--json-only`成功；BASICDTYPE保留0:0、7:4、4:7、0:-2，scalar没有range | 采用能力协商的JSON AST适配候选，不写死XML入口 |
| Verilator tree.meta.json | 该Windows构建在filename内输出未转义反斜杠，标准JSON解析失败 | 不用宽松修补掩盖错误；不依赖该sidecar作为唯一来源映射，另生成本方源文件清单；需要它的能力应返回明确错误 |
| 当前SigTree Port | 只有identifier/direction/conn/signal | 不能直接把现有Port当作完整声明manifest，仍需富模型与来源适配 |

工具版本和SHA256已写入证据。本机Yosys实际版本高于仓库构建脚本默认tag，这里仅记录观察结果，不将它当作自动批准整个上板工具链升级。

## 2. 端口声明来源与不猜测策略

拟实现`PortManifestBuilder`读取版本化的声明证据，再与同源Yosys端口表交叉验证。M0先支持一维packed整数范围；struct、多维/未求值类型和未经测试的转义形式明确拒绝，不用正则猜HDL。

| 输入证据 | 接受条件 | 不满足时 |
|---|---|---|
| Verilator JSON AST | 锁定binary hash/适配版本；top层isPrimaryIO、dtype引用可解析；dtype明确为受支持BASICDTYPE；源/top/参数指纹匹配 | `E_PORT_SHAPE_UNKNOWN` / `E_MANIFEST_VERSION`，不继续构建PadMap |
| Yosys bits/offset/upto | 校验方向、位宽、升降序与AST一致；bits里的net id仅作网表标识 | 交叉验证冲突时失败，不用bits[0]当物理脚或C++下标 |
| Yosys single_bit_vector属性 | 只有在对应版本/流程实测支持，且来源和声明一致时使用；明确1代表向量 | 缺属性时不能在未验证工具版本中据width=1推断scalar |
| 标量形态 | 必须有可信声明证据确认无packed range | 不能把未知shape默认scalar |
| 源文件定位 | 本方保存规范源路径、内容hash、top、展开参数；AST的loc只在可验证的文件映射下使用 | 缺可靠映射时不提供伪精确源码位置 |

新版Verilator JSON格式官方仍声明会演进，因此内部节点addr/dtypep只在单次导出内用于解析，不持久化为port_id；公共manifest使用规范top/端口名与声明信息，不泄漏指针式ID。[官方JSON输出说明](https://verilator.org/guide/latest/exe_verilator.html#cmdoption-json-only)。

## 3. 文件与API改造清单

| 文件/目标 | 具体修改 | 必须保留的边界 |
|---|---|---|
| `include/eda/api/port_manifest.hpp`（新增） | PortDecl、PortBitRef、PortManifest；shape显式，hdl_index为optional有符号整数，bit_slot独立 | 不包含wx类型；一份契约供插件与GUI消费 |
| `core/src/eda-virtual-board/PortManifestBuilder.*`（新增） | 验证声明证据/生成bits；不实现板面或外设逻辑 | 来源冲突拒绝，所有合法位显式列出 |
| `ConstraintSheet.h` | PinBindingV2、v2表结构/结果；scalar null与vector0不同主键 | Legacy结构只作迁移入口，不让int=0继续同时表示两种含义 |
| `ConstraintSheet.cpp` | 逐位校验按manifest查找；CST引用统一格式化；导入保存显式下标；v2序列化/迁移 | 不按width阈值筛HDL索引，不静默丢未知字段或未管理CST行 |
| `main/fpga/FpgaConstraint.*` | 替换pair<direction,width>；wx适配无损传递shape/range/bit引用 | GUI层不重新计算不同版本的索引规则 |
| `main/fpga/FpgaPinBindingPanel.cpp` | 根据真实PortBitRef生成/显示/删除行，编辑器用真实引用匹配 | 不能把未知旧绑定自动改线；CST仍为唯一物理连线来源 |
| `include/eda/api/electrical_profile.hpp`（新增） | DevicePadMap、BoardPowerProfile、IOStandardProfile、ExternalEndpointProfile、诊断DTO | 不依赖wx，不从IO_TYPE后缀猜所有电气规则 |
| `core/src/eda-virtual-board/ElectricalValidator.*`（新增） | ValidateElectrical及整组Bank一致性校验 | 无数据/冲突阻止启动，不回退全局LVCMOS33 |
| `PinDatabaseStore.*`与GUI pin data适配 | 引用核准电气profile、去掉不可信自动默认；复用同一Validator | 既有pin数据库不是VCCIO权威 |
| `registry/pins`、`registry/electrical`（新增） | 板卡修订、vendor Bank与供电、I/O规则、来源hash/页码 | 合成fixture绝不安装为Tang生产资料 |
| CMake/测试 | 增加无wx内核目标和真实C++/GUI适配测试；CTest注册fixture路径 | 不以Python参考脚本通过替代C++实现通过 |

索引规则依v1.1固定：slot=i时upto=0→offset+i，upto=1→offset+width-1-i；scalar的hdl_index=null，[0:0]为0。引用格式看shape，不看index是否>0；显示排序与bit_slot分开。

## 4. 电气资料核准与生产启动门槛

本轮已回读官方板卡原理图，**尚未逐脚完成vendor Bank/VCCIO与厂商I/O规则的交叉核准，未写入任何宣称已核准的生产电气profile**。原理图电源轨是证据来源之一，不能靠LED供电或pad编号推出Bank编号。[官方原理图](https://dl.sipeed.com/fileList/TANG/Nano%209K/2_Schematic/Tang_Nano_9k_3672_Schematic.pdf)。

| 所需资料 | 要核准的内容 | 完成之前 |
|---|---|---|
| Tang Nano 9K选定修订原理图 | pad3/4、10/11/13/14/15/16、52、17/18对应网络及供电轨 | 使用资源标识，不给未核准电压标“通过” |
| GW1NR QFN88封装/IO规则 | pad→vendor_bank、专用脚能力、IO_TYPE按方向的VCCIO范围与例外 | `E_BANK_UNKNOWN` / `E_ELECTRICAL_UNSUPPORTED` |
| 实际板卡配置 | 固定/可选VCCIO配置、是否存在电平转换 | `E_VCCIO_UNKNOWN` |
| 版本来源 | 文档页、修订、hash、核准记录 | 不信任一个verified=true字段；资源版本未满足规则不能启动 |

ValidateElectrical顺序：身份匹配→Pad/Bank存在→VCCIO已知→标准已知→方向/Bank能力→电压兼容→外设端与pull/drive→同Bank全体一致性。缺数据不是warn；至少覆盖`E_BANK_UNKNOWN`、`E_VCCIO_UNKNOWN`、`E_IO_STANDARD_UNKNOWN`、`E_IO_VCCIO_MISMATCH`。禁止在未知项时按原defaultIOType=LVCMOS33继续。

## 5. K1实现顺序与真正验收

| 子步骤 | 产物 | 真实测试 |
|---|---|---|
| K1a 富模型与来源适配 | 声明manifest与诊断；实际工具导出适配 | 从SV到manifest，scalar、[0:0]、[3:0]、[7:4]、[4:7]、负范围与unknown；记录AST不支持/版本错/源不匹配 |
| K1b CST与迁移 | v2绑定、导入/导出/保存/加载/校验 | 真实CstGenerator往返，向量[0]不丢；重复/缺失位/越界位；旧数据有歧义时拒绝自动映射 |
| K1c 电气与数据 | Validator、生产profile和来源 | synthetic全部case转C++测试，再测真实板所用Pad正例及错电压/同Bank冲突反例；两类数据分开 |
| K1d GUI适配与回归 | 无损传递/行生成/错误定位 | 实际wx适配往返保留shape/range，不只测试DTO；原主程序/CST/仿真回归 |

旧`PinBinding::bitIndex`从0基迁移为真实HDL索引不可直接reinterpret。新版显式记录schema和源声明指纹，导入时保留下标语法。旧数据只有在当前声明和原语义能唯一确认时迁移，否则返回需确认诊断；不通过猜名、猜位或补全物理连线让测试通过。

G1关闭条件：引用的两个fixture对应真实C++测试100%通过；工具导出→manifest→wx适配→CST往返通过；生产Pad/Bank/VCCIO证据核准且严格校验；主程序和所选既有回归仍通过。本轮未执行这些新实现，不能因为基线6项回归全过就关闭G1。

```powershell
python tools/virtual/analyze_k1.py
```
