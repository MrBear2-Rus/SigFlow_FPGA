## 生产数据与来源

`registry/pins/tang-nano-9k.6202.reviewed.v1.json`、`registry/electrical/tang-nano-9k.6202.reviewed.v1.json` 随主程序分发。源 PDF 归档于 `registry/provenance/`；每份记录版本、物理页、URL、SHA256。原理图首页修订历史包含 6202（2022-10-23），FPGA 页是 PDF 物理第 2 页、印刷 sheet 3/5。

| 资源 | Pad | 官方 Bank | VCCIO | M0 IO_TYPE |
|---|---|---|---|---|
| LED1～LED6，低有效橙色 | 10 / 11 / 13 / 14 / 15 / 16 | 3 | 1800mV | LVCMOS18 |
| 按键，外接 10K 上拉至 1.8V | 3 / 4 | 3 | 1800mV | LVCMOS18 |
| 27MHz 晶振输入 | 52 | 1 | 3300mV | LVCMOS33 |
| FPGA UART TX / RX，连接 BL702 | 17 / 18 | 2 | 3300mV | LVCMOS33 |

封装核对使用 UG803-1.6.5E 的 **QN88P（PSRAM）列**；公共封装名仍为 QFN88，完整器件型号包含 QN88P。QN88 列有不同引脚，不能混用。DS117-3.2.5E 表 3-11/3-12 为标准和驱动子集来源。

该 profile 是保守的数字教学核准子集：输入、输出都要求匹配名义 VCCIO，不代表完整芯片输入容限；支持输出 drive 4/8/12mA，内部 pull 暂仅允许 none，板载按键的外部上拉另记。inout、差分与其他标准未核准即拒绝。其它 Pad 保留 88 脚表项，但 Bank 为 null，不能通过电气校验。这里的“核准”指来源交叉核对，未声称真实上板测量或人工签字。

旧资源表把 LED3 指向 12、BTN1 指向 16、UART 指向 41/42，并包含不适用的 CH340/WS2812/USB 别名。本轮将资源表收敛为 11 个有来源的 M0 别名；JTAG TCK 修正为 Pad 6，旧测试“Pad 56 是 TCK”的错误断言同步更新。此为必要的事实纠正，未通过保留错误数据来追求旧断言通过。

## 工具与 GUI 的使用入口

先构建 `sigflow_port_manifest`，随后为当前项目明确提供源文件和 top，导出声明阶段 Yosys JSON 及 sidecar：

```powershell
python tools/virtual/export_ports.py --top k1_ports --output .work/k1/ports.json tests/virtual/k1/ports.sv
```

用于 GUI 时，将 `--output` 指向 `<项目>/.sigflow/virtual/declarations/<top>.json`。GUI 优先查找这个独立声明目录，再查找既有 Yosys artifact。声明 JSON 不能代替 nextpnr 使用的技术映射网表，因此使用独立目录并保留现有综合产物。缺少该 sidecar 时 GUI 报错，不按 width 猜测声明。当前声明导出为显式 CLI 操作，尚未自动并入现有 Synthesis Job；这是当前工作流限制。

导出器对同一显式源清单运行 Yosys `hierarchy/proc/write_json` 和 Verilator `--json-only`，不解析 HDL 文本猜类型，不读取格式损坏的 `tree.meta.json`。源文件、工具与两个导出文件有 SHA256；GUI 再检查 sidecar 版本、源摘要和 JSON 摘要。输入变更必须重新导出。当前入口针对无额外 include/参数覆盖的 M0 源列表；复杂编译上下文必须增加适配器，不能静默宣称相同快照。

在 GUI 中按真实 HDL 位选择绑定。新工程 IO_TYPE 初始为空，只允许选择的核准 Pad 提供其自身默认值；未核准 Pad 没有默认标准。Generate 前统一调用完整结构和电气校验。未知/过期 manifest、歧义迁移会显示错误并阻止覆盖保存；原文件不删除，也不按名字自动改线。

V2 文件嵌入完整声明与 source fingerprint，旧 1.0 文件只有在当前声明可唯一解释时迁移：标量的旧 0，或 `[N:0]` 且 N>0。`[0:0]`、偏置范围和升序存在旧语义歧义，返回 `E_LEGACY_BINDING_AMBIGUOUS`，需明确重绑。legacy C++ API 保留供旧插件兼容测试，GUI 全部改走 V2；不将 legacy 生成器作为新会话入口。

## 复现与验收边界

```powershell
./tools/virtual/configure_windows.ps1
python tools/virtual/verify_k1.py
```

脚本重建主程序与全部测试目标，执行 CTest 后生成 JSON、JUnit 和构建/测试日志。当前 Windows 沙箱的 CREATE_NO_WINDOW `cmd` 子进程返回 `0xC0000142`；同一个进程探针在沙箱外正常，因此完整进程回归在沙箱外执行，未修改进程实现来掩盖环境问题。

真实工具 fixture 共 17 个端口位，超过已核准的 11 个板卡 Pad，因此其完整 CST 往返验证**结构和位引用**；真实板卡电气正反例另行覆盖全部 11 脚，绝不伪造额外核准 Pad。GUI 验证为真实 wx 适配层 C++ 调用和主程序构建；未宣称完成鼠标点击或多显示器视觉验收。

K1 通过只关闭 G1/A2/A3。虚拟板 UI、会话运行、LiveTrace、故障可视化与全 M0 验收仍按后续里程碑推进；Web 继续不纳入本轮。
