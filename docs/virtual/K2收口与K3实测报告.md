## 3. K2 实现合同

### 3.1 通用 Verilated 适配器

| 场景 | 实际规则 |
|---|---|
| 端口访问 | 按 `rtl_name` 生成成员访问，按 `PortBitRef` 完整身份检查，再用 `bit_slot` 位移；HDL 下标不直接当 C++ 位移 |
| 标量 / `[0:0]` | 单比特成员直接写入；仍分别检查 null/0 HDL 索引，保留 CST 的声明形态 |
| `[7:4]` / `[4:7]` | slot 与 HDL 索引显式映射；实际编译测试覆盖下降输入到上升输出 |
| 64 位 | 使用 uint64_t 掩码，实测 bit63；Verilator 导出的引用成员通过 `remove_reference_t` 正确转换 |
| 错误引用 | 未知 port、越界 slot、错误 HDL 索引均返回 `E_ADAPTER_REF` |
| 所有权 | 构造、写、eval、读、final 位于模型 owner 线程；越线程 `E_MODEL_THREAD`；第二次 final 为 `E_FINAL_TWICE` |
| 确定性设置 | 单线程 context、固定随机设置，context.time 使用整数 tick；重放校验源/参数/适配器/电气/CST/调度等指纹 |
| 收敛保护 | 编译使用生成器返回的 `VL_USER_FATAL`，Verilator `--converge-limit 256`；不收敛转 `E_NON_CONVERGENT` |

本阶段支持普通可直接表达为 C++ 成员的一维 packed input/output、宽度 1～64。inout、超过 64 位、多维/复杂声明及需特殊名称编码的端口明确拒绝；不假装这些形式已有可运行适配器。尚未支持一般 `--timing` RTL、多时钟或完整外设事件内核。

真实参考一为 `counter.sv/k2_counter`，使用 Tang Nano 9K 6202 生产电气 profile 与真实 CST。参考二为 `shifted.sv/k2_shifted`，含多比特输入、非零范围、上升范围、`[0:0]` 与 64 位信号。第二模块需要大量测试引脚，明确使用 `SYNTHETIC_TEST_FPGA`；必须传 `--allow-synthetic-test-profile`，其数据没有装入生产 registry。第三个 `nonconvergent.sv` 专门验证真实组合环有界失败。

### 3.2 原子提交、持久 ACK 与恢复

每个求值事务按以下顺序执行：

1. 计算候选电气状态，预检全部 DUT 输入。未知/FLT/CON 在任何输入写入前阻断；无 eval、无正常 trace 提交。
2. 写 `begin`，包含 batch_id、evaluation_position 和实际有效输入。随后才写 DUT 输入并 eval。
3. 读取输出，构造端口/Pad 变化；`AppendBatch` 校验并暂存整个 trace 批次。写完整 `prepare`，包含 trace_events、revision、结果和 fence。
4. `LiveTraceStore::Commit` 预先分配新的不可变快照，进入提交屏障；更新仅由 worker 可见的已提交状态缓存，写带校验和的 marker。
5. durable 模式执行 `FlushFileBuffers`（Windows）或 `fsync`（POSIX），成功后才发布 trace 快照/水位；随后完成审计并返回 applied ACK。

屏障失败不发布 trace；状态缓存恢复为前一个提交值，session 进入 Faulted 并结束模型。DUT 内部已经执行的 eval 不做 checkpoint 回滚；不允许继续运行制造成功 ACK。普通状态读取使用已提交输出缓存，不读取可能尚未提交的 DUT 新值。

| 契约 | 实际行为 |
|---|---|
| memory | 同样的批次/marker/摘要合同；只保证进程内提交，不承诺崩溃后落盘 |
| durable | CreateNew 防止覆盖旧 run；独占写锁；事务 marker 与审计记录均有 OS flush；ACK 报告 durable |
| 文件格式 | JSONL envelope 含 seq、previous、payload、sha256；SHA-256 前向链校验次序与内容 |
| 部分尾行 / 未闭合批次 | 返回最后完整前缀，并将文件截断到未提交事务的 begin；重放与 trace 重建只消费 marker 已闭合事务 |
| 完整记录被篡改 | 校验链/marker 错误直接拒绝；不能把完整损坏记录伪装成普通崩溃尾部 |
| 正在写入的日志 | 恢复器也需要独占写锁；不得与活跃 session 并行修复同一文件 |
| 恢复范围 | 验证合同后从零创建新模型并逐 commit 检查输出；另外重建已提交 trace；不是恢复任意内部状态后继续旧进程 |
| 资源边界 | journal 默认 128MiB 上限；超限/写入失败终止当前事务，不静默丢日志 |

日志 public records 包含 run_header、intent、decision、commit、input_commit、control；未提交 begin/prepare 不当作电路 commit 暴露。硬盘/控制器遵守 OS flush 是 durable 模式的前提，本轮实测的是进程崩溃/强杀及文件尾截断，没有进行整机断电实验。

双 digest 算法版本为 `sigflow.sha256-chain.v1`。以不同的域字符串初始化 SHA-256 链；每条纳入记录使用 canonical JSON dump 增量推进。电路链仅包含 commit.position、按 port_ref 排序的 effective_inputs 和 outputs；控制链包含非 header/commit 审计记录，保留 pending、superseded、blocked、input_commit、Play/Step/Pause/Stop 等旅程，排除 durability 字段。额外 Pause 不改变电路链，但改变控制链。缓存当前摘要，普通 get 不重算整段历史。

### 3.3 pulse、暂停与有界错误

| 操作 | 规则 |
|---|---|
| Paused pulse | 只暂存；duration_ticks 为大于零的 u64 十进制字符串；墙钟等待不消耗期限 |
| Step/Play 提交 | 先完整 guard/提交 pressed_state；自动释放期限为 applied_tick + duration_ticks，溢出拒绝 |
| pending/active pulse 与 set/pulse 冲突 | 目标在释放前被 pulse 独占，返回 `E_STIMULUS_CONFLICT`，无隐藏优先级 |
| 释放调度 | 选择最早 clock/release；同 tick 多个释放合并，先数据释放/稳定，再处理重合时钟边沿 |
| Pause 时已有 active pulse | 保留模拟时间期限；继续 Step/Play 才推进与释放；长脉冲跨多次 Step 已实测 |
| Stop | 取消未提交和 active 刺激；final/销毁一次，旧 ReadView 仍可读 |
| 时钟禁用 / 无上升沿 | `E_NO_CLOCK_EDGE`，Paused；同时限制 max_step_events、max_step_ticks，不做无限搜索 |
| 外部零延迟反馈 / 内部组合环 | max_delta 与 Verilator converge-limit 双层限制；`E_NON_CONVERGENT`，Faulted/结束模型 |

短脉冲实测在 tick=1000 释放；长脉冲在 first edge 后保持 active，跨暂停与继续 Step 后仍在 tick=100000 精确释放。二者都没有依赖 sleep 来推进模拟时间。

## 4. K3 数据、快照与缓存

### 4.1 全序与不可变前缀

`EventPosition={tick:u64, delta:u32, event_seq:u64}`。tick 为 1ps 的整数物理时间；JSON tick/seq 使用字符串。排序键为 `(tick,event_seq)`，本 run 的 event_seq 数值也必须全局严格递增；同 tick 的 delta 不允许倒退。delta 不承担唯一键职责。

`AppendBatch` 对完整 span 进行排序、信号 ID、位宽、01xz 值与配额检查；分配成功后才替换暂存缓冲。非法批次不发布、不漏半批。`Commit` 封存新 chunk，使用每页最多 128 个 chunk 的写时复制索引页；旧 chunk 和旧页从不原地修改。每次 session eval 对应一次 revision，即使没有信号变化也使用显式提交 fence，保证 journal/trace 一一对应。

ReadView 持有不可变 snapshot 的共享所有权，冻结 signals、revision、tail 和索引前缀。复制 view 共享同一租约；Reset 仅释放该句柄。writer 追加或 Seal/Stop 后，持有旧 view 的 reader 继续读取旧前缀，不会自动切换最新数据。

| 查询 | 行为 |
|---|---|
| Query | tick 范围闭区间，按原事件次序返回；同信号同 tick 的所有跳变保留 |
| cursor | 绑定 run/generation/revision/view_id/signal/range/offset；跨 view 翻页返回 `E_TRACE_VIEW_EXPIRED` |
| ValueAtPosition | 最后一个不晚于 `(tick,event_seq)` 的值；不会用 delta 代替 seq |
| ValueAtTick | 此 view 中 tick 及之前最后值，不代表此 tick 没有中间变化 |
| 无有效值 | 明确 unknown；invalid、contention、CON 或 x/z 不标为 known |
| SubscribeCommit | 每次成功提交只发一次水位通知，锁外回调；不逐 transition 通知；回调异常不能撤销提交 |
| 写入限制 | 单 writer 线程检查；回调中重入写入拒绝；Seal 后写入拒绝 |

规范 fixture 的实际结果：

| ReadView | tick=100 的 seq | ValueAtTick(100) |
|---|---|---|
| revision 1 | 10 | 0 |
| revision 2 | 10、11、12 | 0 |
| revision 3 | 10、11、12、13 | 1 |

新提交不会改变旧 view 的任何结果。Query 扩展位置与兼容投影都保留重复时间戳，绝不把 delta=1/2 伪装成额外 1/2ps。

### 4.2 revision 缓存与会话集成

CachingTraceSource 的 live 缓存身份包含 run_id、generation、trace_revision，另加 query_mode、signal、range。先固定 `PinReadSource()`，再从同一固定前缀获取 key 和数据，避免 RefreshReadView 与查询竞争时“新 key/旧数据”或相反。嵌套 wrapper 转发固定 source、时间域和身份；离线 source 使用兼容默认值。

真实离线 VCD 后端的 Query/ValueAt、命中、重开与超预算条目不缓存均有回归；原 20 项既有测试同时保留。live 使用 Physical/1ps，不退化成周期坐标。

VirtualSession 在 guard 通过后收集时钟、输入、输出和 CST Pad 的变化，Pad 保留原始 STATE。ACK 附带 `trace:{run_id,generation,revision,tail_event_seq,committed_through_tick}`。未知候选输入只进入 guard 诊断，不污染正常已提交 trace。输出连接故障图尚未实现，因此当前 pad trace 代表已验证 CST 直连路径。

默认 trace 配额为 2,000,000 records、256MiB、100,000 chunks、256 个活跃读视图。实现对元数据、租约、chunk 和 COW 索引采用保守预算；不把配额当作精确 RSS 测量。超限明确背压/拒绝，不静默截断数据；session 中事务失败会进入 Faulted。当前 Query 以不可变页/块扫描，未实现长期大规模 trace 的逐信号稀疏索引；需要长课时连续运行时应另做性能优化与基准。

## 6. 复现与接入示例

在工程根目录，按既有 Windows 工具链完成配置；本次 CMakeCache 开启了可选 TSan：

```powershell
.\.work\cmake-python\cmake\data\bin\cmake.exe -S . -B build-m0 -DSIGFLOW_ENABLE_WSL_TSAN=ON
python tools/virtual/verify_k23.py
```

该配置需要已安装的 WSL Ubuntu-24.04、g++ 与 setarch。未准备 WSL 的开发机可将选项设 OFF，默认运行 27 项；应明确记录未执行 TSan，不能沿用本机的 28 项结论。统一脚本依照当前机器已核准的 `E:/sigflow_fpga/toolchain/mingw64` 工具布局运行；可移植工具发现不是本阶段交付。

只执行真实 RTL：`python tools/virtual/verify_k2.py --build-dir build-m0`。脚本先调用 `export_ports.py` 的真实 Verilator/Yosys 路径，然后执行：

```text
build-m0/sigflow_adapter_codegen.exe <export.ports.v2.json> V<top> <generated_adapter.cpp>
```

生成器输出所需编译定义；通用 runner 链接 `eda_virtual_runner`、CST 插件、`eda_virtual_board` 和 `eda_platform`，具体命令完整记录于 K2 汇总。不得遗漏 `VL_USER_FATAL`，或用旧 runner 二进制代替当前 Core；测试每次强制重链接。

```json
  "durability":"durable", "journal_path":".work/counter-lab-new.journal",
  "inputs":[
    {"target":"key_p3","package_pin":3,"fixed_drivers":[{"driver_id":"board-pullup","state":7}],"initial_manual_state":2},
    {"target":"reset_p4","package_pin":4,"fixed_drivers":[{"driver_id":"board-pullup","state":7}],"initial_manual_state":13},
    {"target":"clock_p52","package_pin":52,"fixed_drivers":[],"initial_manual_state":2}
```

例如以下命令先在暂停中暂存复位释放与按键脉冲，再由 Step 提交。数字 7/13/2 分别为当前 M0 契约的 WHI/SLO/FLT，不将它们当 bool。

```jsonl
{"op":"set","command_id":"reset-release","target":"reset_p4","state":2}
{"op":"pulse","command_id":"key-pulse","target":"key_p3","pressed_state":13,"released_state":2,"duration_ticks":"1000"}

{"op":"get"}
{"op":"pause","command_id":"pause-1"}
```

GUI 后续接入可通过 worker/任务层调用 Submit，持有 `Trace()`；commit 回调只合并记录水位，在 UI 线程刷新 LiveTraceSource 的 ReadView 并调度绘制。控件不直接写模型，回调也不直接访问 wx 控件。需要分页固定前缀时持有 ReadView 或固定的 PinReadSource，不在分页中反复刷新最新 view。
