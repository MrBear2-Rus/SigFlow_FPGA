## 复现入口

项目先准备固定CMake、兼容GCC/wx、依赖包，随后执行：

```powershell
python tools/virtual/bootstrap_dependencies.py --wx-source E:/sigflow_fpga/source/3rd/wxWidgets-src --wx-build-lib E:/sigflow_fpga/source/build-gcc/wxWidgets/lib
python -m pip install --target .work/cmake-python --cache-dir .work/pip-cache cmake==3.30.2
& ./tools/virtual/configure_windows.ps1
& ./.work/cmake-python/cmake/data/bin/cmake.exe --build build-m0 --parallel 6 --target sigflow eda_sim_verilator_smoke eda_sim_frontend_smoke eda_constraint_sheet_smoke eda_gowin_cst_smoke eda_target_profile_smoke eda_wave_vcd_smoke
& ./.work/cmake-python/cmake/data/bin/ctest.exe --test-dir build-m0 -R '^eda_(sim_verilator|sim_frontend|constraint_sheet|gowin_cst|target_profile|wave_vcd)_smoke$' --output-on-failure
python tools/virtual/verify_k0.py
```

命令行复现时将实际MinGW `bin`加入当前进程PATH；configure脚本内部的环境不向父进程传播。`verify_k0.py`提供`--mingw/--shell/--cmake`参数；bootstrap路径是本机已有资源位置，不是产品发行时可依赖的固定位置。全新机器需准备同版兼容依赖。

原始配置、构建、CTest、模型生成/编译、VCD和交互stderr保留于`.work/k0/`，不进入版本库。长期可评审的有界结果快照进入`docs/virtual/evidence/`；重新实测后运行`archive_stage_evidence.py`更新快照。

## 已发现问题与未完成边界

最初本地Git clone被MSYS命名对象权限拦截，提升权限后完成；没有修改只读基线。已有CMake副本缺Modules，因此在项目内补装固定版本。原生成runtime要求legacy `sc_time_stamp()`符号，尖峰提供兼容stub，同时实际时间由VerilatedContext显式整数更新。GNU Make最初缺uname，测试入口在本项目`.work/k0/posix-tools`准备原生BusyBox uname applet，不改runtime源文件。

K0尖峰不是生产`VirtualSession`：未接CST/PadMap、Bank校验、未知输入guard、五阶段完整调度、LiveTraceStore、journal或GUI。测试fixture按明确端口驱动DUT，不是通过端口名猜测板载连线。未启动桌面界面做交互验收，未实测完整JobService→插件→runner端到端链；已完成的是主程序构建和两条真实RTL运行。

不在本轮开展Web、Proteus二进制运行、真实板下载或后续K2–U1工程实现。M0最终A1–A10仍以v1.1规格逐项验收。
