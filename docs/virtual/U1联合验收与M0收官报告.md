## 1. 工程装配与错误定位

| 入口/模块 | 生产行为 |
|---|---|
| 虚拟实验箱「加载 M0 参考计数器」 | 读取 `examples/virtual/counter/virtual.project.json`，无需选择 runner 或会话 JSON |
| 「构建并启动当前工程」 | 从当前工程根目录读取 `virtual.project.json`；已有 `sigflow.project` 时，以其中的真实顶层及源文件列表装配，时钟、板卡、CST、输入角色仍须显式声明 |
| 「加载实验配置」 | 直接选择任意 `virtual.project.json`，以该文件所在目录为工程根目录 |
| `VirtualProjectSessionBuilder` | GUI 异步子进程传输与生命周期管理；不会在 wx 线程执行 DUT/eval、编译或忙等 |
| `build_virtual_project.py` | 真实双工具声明导出 → `sigflow_session_validate` → 通用适配器生成 → Verilator → MinGW → 唯一会话配置 → 持久 runner |
| `ValidateVirtualProject` | CLI 与 runner 共用的生产门禁，调用 `ConstraintSheetV2`、`ValidateElectrical` 和板卡拓扑；在 DUT 创建前拒绝不合法绑定 |
| 诊断定位 | 列出错误码、真实 HDL 标签及 PortBitRef、物理 Pad、Bank、VCCIO、修复建议；双击诊断关联 Pin Binding 原始下标行，不压缩 `[0]` 或非零范围 |

明确阻断 `E_MISSING_BINDING`、`E_CST_UNMANAGED`、`E_CLOCK_BINDING`、`E_BANK_UNKNOWN`、`E_VCCIO_UNKNOWN`、`E_IO_VCCIO_MISMATCH` 等。教学漏绑只允许通过显式 `allow_unbound_outputs=true` 开放输出位；未绑定输出保持悬空，必需输入和晶振不能因此放行。

缓存位于 `.work/virtual-project-cache/<sha256>/`。指纹覆盖声明源、CST、板卡、电气资料、导出/构建脚本、工具二进制、静态库、公共头文件及 Verilator runtime/编译选项。缓存使用进程锁和完成标记，校验产物 SHA 后才能复用；每次复用仍执行生产绑定/电气校验。编译期间输入变更会拒绝发布完成标记，防止将不同源码快照装配为同一 runner。每个会话使用独立 run ID 和 Journal 路径，避免 durable 文件互相覆盖。

## 2. 同 tick 波形与输入恢复

| 能力 | 最终实现 |
|---|---|
| Multi-Delta 数据 | 从固定 ReadView 的 `LiveTraceSource::QueryExtended` 分页取完整扩展事件，按信号及物理 tick 分组 |
| 共用渲染 | `WaveformRenderData` 携带事件组，软件和 GL 的共用文字层在信号轨绘制菱形和 `ΔN` 标记 |
| 物理时间 | 所有微步仍在同一个 `WaveformTimeToX(tick)`；不把 delta 伪装成 ps 宽度 |
| 检视 | 点击标记后，面板列表显示该 tick 的全部 `tick/delta/event_seq/value/state_code/valid/contention` |
| 实时刷新 | 控制命令优先于历史 trace 分页；空的 revision=0 也建立 LiveTrace 源，初始化 UnknownInput 不再等待首个提交 |
| 观察窗口 | 已缩放的实时波形窗口保持位置；完整范围模式随新提交扩展，避免每个刷新强制 ZoomReset |
| 手动 VCD | `FollowLiveTrace` 由主窗口和验收宿主共用；用户选中的离线 VCD 不会被后续会话通知抢走，显式打开实验箱可重新选择实时源 |

虚拟板和故障面板同时显示阻断原因、`attempted_position`、`last_committed_position`、原始 STATE 和驱动来源。按键、输入驱动或撤销故障在 Paused 时保留 pending，Step/Play 才提交。阻断的输入不写入 DUT，修复后从保留边界继续；输出支路开路只改变拓扑与端点波形，不触发 UnknownInput 暂停。

故障面板提供 LED0、KEY3、KEY4、晶振走线的开路/恢复，以及 P3/P4 的 FLT、SLO、CON 输入驱动。输入 CON 的撤销同样走 pending→Step/Play 的正式协议。`E_NO_CLOCK_EDGE` 和真实 RTL 不收敛的 `E_NON_CONVERGENT` 显示在实验箱错误区；不可恢复的 runner 错误通过重新构建/启动开启新会话，不伪造继续运行。

## 3. 确定性重放与生命周期

| 操作 | 协议/验证 |
|---|---|
| 重放当前日志 | `replay.current`，默认 3 次，可选 1～10 次，每次创建新的 DUT 从零执行 |
| 重放指定 Journal | `replay.file`，读取已关闭日志；沿用日志原始 run/generation，其余源码、适配器、CST 绑定、板卡、电气和调度指纹严格匹配 |
| 校验结果 | GUI 显示 passed/rejected、匹配 commits、circuit/control 两个 digest 及每次重放结果 |
| 原会话 | Running 须先 Pause；Stop 后只读重放通道保留，不为重放修改原电路状态或追加控制日志 |
| 文件处理 | 指定 Journal 的恢复解析不启用尾部修复，不改写用户选中的日志 |
| 关闭 | EOF 使有界会话 worker 完成 final 和 Journal 关闭；独立回收器继续排空旧输出，异常退出超过 2 秒时有界终止所属进程；回调不保留已销毁窗口地址 |

主窗口继续使用原六区骨架：中区局部页签「设计画布 / 虚拟实验箱」，底部「实验故障」与既有终端/波形并列。没有改写全局快捷键表；Space 单步和释放按键只在板面控件获得焦点时处理，丢失焦点、丢失鼠标捕获和 Esc 均释放按住状态。新控件尺寸使用 DIP，绘制颜色来自 UiTheme Token；工具条与故障控制行按可用宽度换行。
