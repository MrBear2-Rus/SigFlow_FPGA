## 3. 故障事务、调度与 guard

新增 `fault.apply`、`fault.revoke`。故障 ID/边 ID 稳定，M0 只支持 open；permanent 直到 revoke，transient 使用 `[start_tick,end_tick)`。错误窗口、未知边/故障、非法触发类型或配额超限明确拒绝。重发相同 command_id 保持原语义；同 fault_id 暂存意图按最后请求合并，旧请求保留 superseded 关联。

| 阶段 | 实际实现 |
|---|---|
| Paused 接收 | 只记 intent/control 并返回 pending；已提交 board、输入写入数、eval 数和 trace 不变化 |
| 0：拓扑提交 | Step/Play 或 Running 安全边界提交连接状态，`evaluated=false`，不写 DUT、不 eval；同样经过 begin/prepare/marker/OS flush/trace publication |
| 1：外部激励 | 合并输入候选、解析全部输入 Pad；任何未知在第一位 DUT 写入前拦截 |
| 2：时钟 | 按整数有理时钟推进，仍由唯一 PadMap 导入；没有时钟边沿则有界报错 |
| 到期故障 | 调度器在 clock、pulse release、fault start/end 中取最早 tick；同 tick 先拓扑，再数据，再时钟；不按 ps 空转 |
| 恢复 | revoke 或窗口 end 在拓扑边界立即重连；不等待下一次 RTL 输出改变 |
| Stop | 取消未提交故障/输入，保留最后已提交故障状态与证据；模型 final/销毁一次 |

拓扑独立提交是必要的：打开输入线可以先成为已提交事实，下一次输入导入才被 UnknownInput 拦截。报告 `last_committed_position` 时使用刚完成的拓扑 fence，不宣称回滚到前一个完整 tick；也没有 DUT checkpoint 回滚能力。

| 场景 | DUT 行为 | 板级观测 |
|---|---|---|
| 初始化 FLT / CON | 输入写入数=0、eval=0；Paused(UnknownInput) | guard 给出具体 Pad、STATE、来源与尝试位置 |
| 异步复位 CON | 非时钟提交前阻断，无输入写入/eval/正常 trace 新批次 | 保留上次稳定状态和候选 guard 诊断 |
| `wire.clock` 或无上拉输入边开路 | 下一导入前阻断；不先转换为 bool | 输入 Pad 为 FLT，保留精确断点 |
| `wire.key3` 开路、Pad 上拉仍在 | 正常采样 1 | Pad WHI；接触点与 Pad 可分别观测 |
| `wire.led0` 开路 | 输出 ObserveOnly，DUT 正常计数 | `pad.10` 仍 SLO/SHI 翻转，`led0.K=FLT(2)`、lit=false |

LiveTrace 订阅原有 `port:<HDL>` / `pad:<pin>`，另外独立记录规范节点 `pad.10`、`led0.K`、连接 `wire.led0` 和 `led0.lit` 等。端点变化、原始 STATE/有效性和边状态同批提交；不能通过两个别名指向同一个不可断开的变量来伪造开路。

## 4. Journal 与确定性重放

合同升级为 `sigflow.session-journal.m0.v3`、`sigflow.scheduler.m0.v3`、`sigflow.sha256-chain.v2`。run_header 增加规范板卡 JSON 的 SHA-256、显式时钟角色和漏绑策略；此前源、适配器、CST/电气、时间及 resolver 指纹继续校验。旧合同不会静默按新语义重放。

每条 commit 保存 `evaluated`、`board_inputs`、`clock_high`、完整 `faults`、节点/边/LED `board` 快照、DUT outputs、实际导入输入和 trace_events。fault_commit / fault_boundary 审计保存故障 ID、位置与生效/恢复现场。Snapshot 提供 `topology_position`、pending_faults、binding_diagnostics 和最新 trace 水位。

| 重放检查 | 规则 |
|---|---|
| 求值位置 | evaluation_position 和提交 fence 同 tick/delta，起始 seq 接续上一个 fence；同 tick 全序继续严格递增 |
| 输入 | 从已提交的板卡驱动和拓扑重新 resolve，写模型前核对每位有效性、STATE 与采样值 |
| DUT | 只有 evaluated=true 的事务写输入/eval；每次输出逐位核对；topology-only 不伪造 eval |
| 板级 | 依据实际重放输出、原 CST 和该事务有效连接重新求全部 Pad/外设端点/LED，与 board 快照逐项比较 |
| Trace | 重算变化事件、STATE、valid/CON、顺序与 fence，逐条比较 trace_events；RestoreTrace 只恢复 marker 完整批次 |
| 摘要 | circuit 链加入 board/faults/evaluated；control 链保留意图、阻断、替换、边界和控制旅程；不使用鼠标墙钟 |

正常与开路/恢复的真实运行各从零重放三次，分别要求 circuit、control、匹配 commit 数完全一致。三次一致是同一条运行的重复重放要求，不要求正常与故障运行的电路摘要彼此相同。原生测试还主动篡改端点快照，确认返回 `E_REPLAY_BOARD_DIVERGENCE`。

原有 durable 独占锁、SHA 校验链、marker 显式 FlushFileBuffers/fsync 和截尾恢复继续使用。memory 仍不承诺磁盘持久化。从零重放不是从任意中间状态继续运行旧模型。
