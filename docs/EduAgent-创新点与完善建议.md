# 教育版 / 工程版 Agent：创新点与完善建议

> 版本：v1.0 · 2026-10-03
> 范围：SigFlow 教育版 Agent 与工程版 Agent 的**产品能力**建议，不涉及本轮代码改动。
> 依据：本仓库 `docs/edu-agent/{sigflow,ucagent}/` 的 spec 与 task、`contracts/edu-agent/v1/` 契约，
> 以及 2026-10 期间在 `core/src/eda-agent-gateway/`、`InnerPlugin/`、`tests/agent/` 上实际调试所得。
> 标注约定：**【观察】**= 我在本仓库代码/运行中实际看到的事实；**【推断】**= 基于架构的合理设想，尚未验证。

---

## 0. 先说结论

教育版目前已经把「**证据可信**」这条线做得相当扎实：不可变快照、内容寻址、
grant/receipt 门控、幂等、事件游标、报告归一化、波形精确查询——这些是**信任地基**，
在同类教学工具里并不常见，是真正的护城河，值得继续保持。

但**教学价值**这条线还偏薄：现在的 Agent 更像「一个会解释报错的助手」，
而不是「一个会设计学习路径的助教」。下面 12 条里，前 6 条偏**创新**（做出别人没有的东西），
后 6 条偏**完善**（把已有能力补成完整体验）。每条给出依据、建议、价值与成本。

---

## 一、创新点（做别人没有的）

### 1. 「同一时刻」四视图联合锚点：把波形变成因果链的入口

- **【观察】** 现在四视图各自有 ref：`source-ref`（RTL 行列）、原理图 node_id、
  波形 `artifact_id + signal_id + tick`、报告 diagnostic。`POST /waves/{a}/query` 已能返回
  闭区间精确跳变、`initial_value`、x/z 保留。但它们是**并列的证据**，没有"联合"。
- **建议**：新增「时刻锚点」（instant anchor）概念——给定 `(artifact_id, tick)`，
  一次返回该时刻**全部**相关信息：哪些信号在该 tick 发生跳变、这些信号对应哪些 RTL 行、
  该 tick 落在哪个诊断的时间范围内、原理图上哪些节点受影响。
  学生点波形上任意一个异常时刻，直接得到"这一刻发生了什么、为什么"。
- **价值**：这是 EDU-03 从"能查波形"升级到"能解释波形"的关键一步。
  时序类错误（复位释放、亚稳态、竞争）**本质上只能靠时间维解释**，
  而现有教学工具几乎都停留在"看图说话"。
- **成本**：中。需要一个新的联合查询路由 + 一张 `signal → source_ref` 映射表（见第 7 条）。

### 2. 证据强度分层：让学生看见"这是事实，还是猜测"

- **【观察】** `diagnostic.schema.json` 已有 `confidence_kind ∈ {tool, rule, hypothesis}`，
  `origin ∈ {core, legacy}`，`completeness ∈ {complete, partial, unavailable, legacy_unverified}`。
  字段齐备，但**教学侧还没有把它变成产品语言**。
- **建议**：把证据强度做成学生可见的三档标识，并驱动教学语气：
  - `tool` + `complete` →「工具确定的」：可以直接讲结论。
  - `rule` →「规则推断的」：讲结论但说明依据。
  - `hypothesis` 或 `partial`/`unavailable` →「这是推测，需要你验证」：**必须**给出验证动作。
- **价值**：直接对应 spec 里"不能把空 diagnostics 当无问题""不制造假诊断"的要求，
  同时把**科学素养**（区分事实与推断）变成产品行为，而不是文档里的口号。
  这也是对抗"模型一本正经胡说"最实用的产品级防线。
- **成本**：低。字段已有，主要是 UCAgent 侧的策略与 SigFlow 侧的展示约定。

### 3. 快照对比教学：把"改对了"变成可复现的证据

- **【观察】** 快照 id 是内容寻址的（`SHA-256(input_fingerprint)`），同输入必得同 id，
  不同输入必得不同 id；Job 与快照、revision 强绑定；报告带 `input_fingerprint`。
  这套机制目前主要服务于"防串版本"。
- **建议**：把它**反用**为教学资产——自动保存"学生出错时的快照"与"修复后的快照"，
  并提供 `POST /snapshots/{a}/diff/{b}` 返回：RTL 差异、两次报告诊断的差异、
  资源指标差异（同目标/同策略才可比）。教师端可据此积累**真实错误案例库**。
- **价值**：EDU-01/EDU-04 的自然延伸。现在"学生改完复测"的结论只活在一次会话里，
  对比机制能让它沉淀成可复用教材，且**全程有 hash 可验证**，不存在"截图说不清"。
- **成本**：中。快照与报告都已具备，主要是 diff 路由与展示。

### 4. 试错配额：用授权机制做教学护栏

- **【观察】** grant 已绑定 `max_jobs`、TTL、`plan_hash`、snapshot、revision，
  `GrantStore::Consume` 在同一锁内原子扣减并持久化 `used_jobs`；receipt 是一次性核销。
- **建议**：把这套机制从"安全边界"扩展为"**教学节奏控制**"：
  例如每节课给 N 次综合配额，用完后不是硬拒绝，而是引导——
  「你已经跑了 8 次，先写下你的假设，再跑第 9 次」。
  配额可由教师按课程配置，并与提示等级联动（用了 L4 参考解法则配额收紧）。
- **价值**：**"暴力试错"是初学者最大的学习障碍**——改一行跑一次，靠工具代替思考。
  用已有的配额机制引导"先假设后验证"，是把工程方法教给学生的最直接手段。
  而且这个机制**技术上已经存在**，只差教学策略。
- **成本**：低到中。后端能力完备，主要是 UCAgent 策略 + UI 文案。

### 5. 故障注入式实验：主动制造错误让学生找

- **【观察】** `DiagnosticParser` 已能解析 Yosys 的
  `file:line[:col]: error|warning|fatal:` 与 Verilator 的 `%Error-CODE|%Warning-CODE|%Info`，
  并保留 `raw_code`、未知码标 `unclassified`。
- **建议**：建一组**受控故障实验**：故意注入锁存器推断、多驱动、位宽截断、
  组合环、未驱动、复位极性错误等，每个附"标准诊断 + 期望定位"。
  学生做"诊断医生"：工具给出原始日志，学生判断根因并定位到行。
- **价值**：与"学生自己写错"相比，**故障可控、可复现、可评分**，
  且能覆盖那些学生自己不容易碰到的错误类型。是 L1–L4 之外的一条独立教学路径。
- **成本**：中。fixture 与课程内容为主，解析器已就绪。

### 6. 教师审计视图：把教学数据变成教学改进

- **【观察】** 事件流带 `sequence`/`event_id`/`trace_id` 且可重放；
  审计索引记录 trace_id、request_id、grant/job、动作与结果；receipt 记录 L4 是否被核销。
- **建议**：在**去标识化**前提下，给教师一个聚合视图：
  本节课学生问了哪些 issue、分别停在几级提示、多少人看了 L4、
  哪些诊断反复出现、平均独立修复率。**不给学生排名**，只用于改进教学。
- **价值**：现在这些数据只用于调试与合规，浪费了它的教学价值。
  同时它比"问卷"客观得多，因为每个数字背后都有可追溯的 Job/事件。
- **成本**：中。数据已在，需聚合查询 + 隐私边界设计（**这条必须先过隐私评审**）。

## 二、完善点（把已有能力补成完整体验）

### 7. 设计映射的降级要"诚实且可理解"

- **【观察】** SF-07 要求 `mapping_status ∈ {unavailable, ambiguous, stale}`，
  task 里也写明"无映射时只显示可信模块/源码，不能高亮猜测对象"。
  但四视图定位（SF-10）依赖 `node_id`，而 `node_id` 在重新解析后可能失效。
- **建议**：把降级做成**一等公民**而不是兜底：
  明确"能定位到行 / 只能定位到模块 / 完全无法定位"三档，
  并在 UI 上直接说明原因（如"综合已优化该信号，无法对应到 RTL"）。
  同时把 `signal → source_ref` 映射缓存为可失效的版本化数据。
- **价值**：**"跳不过去"比"跳错"好得多**。学生被错误高亮误导的代价远高于"这次定位不了"。
  这也是第 1 条联合锚点的前置条件。
- **成本**：中。依赖 SigTree/VerilogManager 的映射稳定性。

### 8. 工具链前置条件自检与可操作指引

- **【观察】** 本机实测：`verilator --binary` 需要**两个** Windows 上常缺的前置条件——
  ① 可运行的 `python3`（`verilator_includer` 的 shebang 是 `#!/usr/bin/env python3`），
  而 Windows 上 `python3` 常被解析到 **0 字节的 Microsoft Store 占位程序**（存在但执行失败，cmd 报 9009）；
  ② POSIX shell（`verilated.mk:255/270` 用 `if test ... then ... else ... fi`，
  `cmd.exe` 无法解析，报「此时不应有 0。」且 `make` 以 255 退出）。
  此外 `verilated.mk:81` 调用 `uname -s`，Windows 上会产生 `pipe: No error` 警告（非致命）。
  当前失败只表现为 `exit code 1`，**完全不可诊断**。
- **建议**：在启动真实工具前做显式探测，并把结论写进 Job 日志与报告诊断：
  - `python3`：**实跑 `--version` 检查退出码**，不能只看文件是否存在；
    失败时提示"请关闭 Windows 的 python3 应用执行别名，或安装 Python"。
  - POSIX shell：检查 `SHELL` 与 PATH 上的 `sh`/`bash`；
    缺失时提示"Verilator 的 makefile 需要 POSIX shell，请安装 Git for Windows 或 MSYS2 并将其 `usr/bin` 加入 PATH"。
- **价值**：把"环境缺失"和"链路故障"分开，学生/老师一眼知道该装什么。
  顺带把**读工具链错误**这件事本身变成工程素养教学内容。
- **成本**：低（探测逻辑）+ 中（随包补齐依赖涉及许可证与体积，见第 12 条）。

### 9. 降级链透明化：让 `producer` 成为学生可见的状态

- **【观察】** D-03 要求冻结 `model / mock / rule` 三种输出的 `producer` 标识，
  且"无模型降级与错误展示"是明确要求。字段在契约里，但体验上容易被忽略。
- **建议**：把当前模式做成**常驻可见**的状态（而非只在出错时提示）：
  「当前：真实模型 / 规则模式（无 Key）/ Mock（开发）」。
  规则模式下明确说明"以下是基于规则的提示，不是模型生成"。
- **价值**：避免学生**误以为 AI 在思考**——这既是诚实性问题，也影响学生对提示的信任度。
  在无 Key 或断网场景下，清楚的模式标识比"看起来还能用"更有教育意义。
- **成本**：低。标识已有，主要是 UI 常驻展示与文案。

### 10. 预测—验证闭环：把"先猜后测"变成可累积的证据

- **【观察】** UA-07 提到"先预测再观察"的交互设计；`OutcomeChecker` 负责用新 revision 的
  真实 Job 与旧 Job 对比，且强调"工具成功 ≠ 功能符合预期，也不等于学生掌握概念"。
- **建议**：让学生**显式写下预测**（"我认为复位释放后第一个有效边沿会出现在第 N 个周期"），
  再用真实波形比对，并记录"预测—实测"是否一致。累积成学生的**自我校准指标**。
- **价值**：这是把"仿真"从"看结果"变成"验证假设"的关键设计，也是工程思维的核心。
  与第 4 条（试错配额）配合，形成"假设 → 验证 → 修正"的完整循环。
- **成本**：中。需要交互与存储，且**要避免变成评分压力**（指标只给自己看）。

### 11. 离线优先的课程引用与缓存降级

- **【观察】** UA-09 要求 `passage_id`/`course_version`/`content_hash`/`retrieved_at`，
  且"运行时网络断开仍能显示缓存摘要、链接和缓存日期"；链接必须来自受控元数据回填。
- **建议**：把离线降级做成**默认路径**而不是异常路径：
  缓存命中时显示摘要 + 来源 + 缓存日期；失效链接显示"来源与缓存时间"而不是空白；
  并明确标注"这是缓存的课程内容，可能不是最新版"。
- **价值**：课堂网络不可靠是常态。**能优雅降级比"联网才可用"实用得多**，
  且缓存日期可见避免了"引用了过期教材"的隐患。
- **成本**：低到中。契约已规定字段，主要是实现与 UI 状态。

### 12. 随包运行时依赖与许可证清单（发布阻塞项）

- **【观察】** `external/fpga-tools/runtime/` 已随包 Yosys 0.49 与 Verilator 5.052，
  但 Windows 上缺少 Verilator `--binary` 所需的 `python3` 与 POSIX shell（见第 8 条）。
  另外 `verilator_bin.exe` 实为 688 字节的 **perl 包装脚本**（`#!/usr/bin/env perl`），
  因此还隐含 perl 依赖——本机能跑通说明 perl 恰好存在，但**这属于未声明的隐式依赖**。
- **建议**：明确随包清单与**显式声明**所有隐式依赖（python3、POSIX shell、perl），
  逐项过许可证（Git for Windows 为 GPLv2、MSYS2 组件各自不同、Python 为 PSF），
  并写进发布材料与安装说明；无法随包的依赖给出**可操作的手动安装指引**。
- **价值**：这是"两平台新装可重复"（SF-04 完成条件）能否成立的前提。
  **隐式依赖不声明，等于把故障留给用户**——本机这次遇到的正是这种情况。
- **成本**：中到高。主要是许可证审查与打包体积，需要 U1/S1 联合决策。

## 三、优先级建议

| 优先级 | 条目 | 理由 |
|---|---|---|
| **P0（先做）** | 8 工具链自检、12 依赖清单 | 当前真实工具**跑不通且不可诊断**，是 G1 的直接阻塞 |
| **P0** | 2 证据强度分层 | 字段已具备，成本最低，直接兑现 spec 的"不造假诊断" |
| **P1** | 1 联合锚点、7 映射降级 | EDU-03/EDU-02 的体验分水岭，互为前置 |
| **P1** | 4 试错配额、10 预测—验证 | 教学法创新，后端能力已备 |
| **P2** | 3 快照对比、5 故障注入 | 教学资产沉淀，依赖课程建设进度 |
| **P2** | 6 教师审计、9 降级透明、11 离线引用 | 体验完善，其中 6 需先过隐私评审 |

## 四、两点提醒

1. **不要把"能跑"当成"教会了"**。第 4、10 条针对的正是这个陷阱：
   工具跑通、诊断正确，都不等于学生理解了。验收标准里已经写了这一点，
   产品设计上也要让它体现在交互里，而不只在文档里。
2. **第 6 条（教师审计）有隐私风险**。学习数据的价值很高，但"可追溯"与"可监控"只差一步。
   建议先定边界（去标识化粒度、保留期、学生可否查看自己的数据），再动手实现。
