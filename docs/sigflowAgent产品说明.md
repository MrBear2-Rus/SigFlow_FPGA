## 1. 产品概述

### 1.1 定位

SigFlow 原生教学 Agent 是 SigFlow EDA IDE 的 **LLM 驱动的教学服务子系统**。它站在 FPGA 经验者（设计者）的角度，把教学法固化成 Agent 工作流，让使用 SigFlow 的学生在真实 FPGA 工程流（画原理图/写 Verilog → 综合 → 布线 → 烧录）中，被持续引导着从 LLM 身上蒸馏硬件设计知识。

一句话：**不是「再做一个聊天框」，而是把 Agent 原生化，让 LLM 能感知项目结构、读取工具链报错、了解学生学习历史，并据此提供「引导而非答案」的教学服务。**

### 1.2 核心价值主张

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   现在的 DS 插件          vs        原生教学 Agent             │
│                                                             │
│   • 学生主动去问            • 结合报错/项目主动引导           │
│   • 不知项目结构            • 感知项目文件、约束、日志         │
│   • 不能读工具链输出        • 读 yosys/nextpnr 报告           │
│   • 不了解学生水平          • 记录学习历史、个性化提示         │
│   • 和网页聊天框无区别      • 嵌入 IDE、引导式教学             │
│                                                             │
│   本质区别：一个是被动答问，一个是「有上下文的助教」           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 与现有系统的关系

本产品**不是从零开始**。SigFlow 已经有一层**确定性诊断层**（不依赖 LLM，纯代码），本产品在其之上增加 **LLM 教学层**：

```
┌──────────────────────────────────────────────────────────────┐
│             SigFlow IDE（根目录 SigFlow_Cmake/）              │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  新增：原生教学 Agent（LLM 层，本项目）                 │  │
│  │  · LangGraph 双分支 · L1-L4 分级引导 · RAG · 学生画像   │  │
│  └──────────────────────────┬─────────────────────────────┘  │
│                             │ MCP / JobReport JSON            │
│  ┌──────────────────────────▼─────────────────────────────┐  │
│  │  已有：确定性诊断层（L1-L4 中「识别错误」的部分）         │  │
│  │  · jobs/ 统一 Job 框架（JobService + JobServiceRegistry）│  │
│  │    → 产出统一 JobReport{errors[]}                        │  │
│  │  · FpgaYosysLogParser（ruleId → error.code）             │  │
│  │  · NextpnrLogParser（chineseDesc → error.summary）       │  │
│  │  · CstValidator（约束验证）· platform/（跨平台进程/路径） │  │
│  └─────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

关键分工：**「识别错误」是确定性代码（已存在，100% 可靠）；「如何引导学生学习」交给 LLM 层（本项目新增）。**

## 2. 背景与问题

### 2.1 大学生学习范式的变化

LLM 具有庞大知识储备，现在很多学生的学习是「蒸馏大模型」——不再 Google/百度/查文献/翻教材，而是直接接受 AI 输出。对学习场景，AI 输出「几乎可信」。问题是：**直接给答案，学生独立调试能力下降**（GitHub Copilot 内部遥测：给直接答案 → 独立调试能力 -27%；仅给提示 → +14%）。

### 2.2 现有 DS 插件的痛点

SigFlow 已有 DeepSeek 插件，但它与「后台网页开个 DeepSeek 聊天框」没有本质区别：

- 需要学生**主动去问**；
- **不知道项目结构**（读不到代码/约束/日志）；
- **不能干涉开源工具链**（看不到 yosys/nextpnr 报错）；
- **不了解学生学习情况**（无法个性化）。

### 2.3 本产品要解决的问题

| # | 问题 | 本产品的答案 |
|---|------|-------------|
| 1 | 学生被动问 | 结合工具链报错**主动引导** |
| 2 | 无上下文 | 感知项目结构 + 读报告 |
| 3 | 给答案 | **L1-L4 分级提示，不给答案** |
| 4 | 千篇一律 | 学习历史 → 个性化提示 |
| 5 | 无课程关联 | RAG → PA/一生一芯 章节链接 |

## 4. 核心能力

本产品 MVP 交付三大教学能力（教学优先），外加双分支框架预留工程能力。

### 4.1 能力一：报错 → L1-L4 分级引导

当开源工具链报错时，Agent **不直接甩修复代码**，而是经 LLM 处理后生成教学引导：错误原因、涉及知识点、调试思路、下一步建议。

**L1-L4 分级语义（冻结，对齐 D-06）**：

| 级别 | 语义 | 学生拿到什么 |
|------|------|-------------|
| **L1** | 方向性提问 | 「你的组合逻辑里，某个信号在某些分支好像没有被赋值。想想 always 块里漏了什么？」 |
| **L2** | 缩小范围 | 「问题出在时序逻辑和组合逻辑的边界上。检查 always 的敏感列表和分支覆盖。」 |
| **L3** | 具体线索 | 「在 case/if 分支不全时，综合器会推断出一个『保持原值』的元件。这是什么元件？」 |
| **L4** | 参考解法（需二次解锁） | 给出完整修复，但需要学生**二次确认**「我真的要看答案」才展示。 |

**升级由确定性引擎控制**（不是 LLM 说了算）：学生请求更多 / 多次报错 / 主动放弃 → 升一级；连续同类错误 3 次 → 提示「你已经试了 3 次，要更直接的提示吗？」。**「哪些错误类型允许到 L4」有门控规则**（D-06）。

**示例——锁存器推断（L1-L4 全程）**：

```
学生综合 fulladder 报 warning：latch inferred for signal 'sum'

Agent 输出（L1）：
  ⚠ 综合器提示：你的 'sum' 信号被推断成了一个「锁存器」。
  💬 你能说说，什么样的代码会让综合器推断出锁存器吗？
  （不给答案，先让学生想）

学生：不知道……

Agent 输出（L2）：
  📖 提示：当一个信号在「某些条件分支」里没有被赋值时，
      综合器会认为它需要「保持原值」，于是推断出锁存器。
  💬 回到你的代码，看看 'sum' 是不是在某个分支里漏了赋值？
  📚 PA 相关：组合逻辑的完备性（链接）

学生：还是找不到……

Agent 输出（L3）：
  在 always @(*) 块里，如果 if/else 没有写全、或 case 缺 default，
  'sum' 就可能在某个分支没被赋值。检查你的 if 是否配了 else。
```

### 4.2 能力二：学习历史 → 个性化提示

记录学生历史（常见错误、已掌握概念、进度、提问偏好），据此**动态定制系统提示词**，让 Agent 的回答贴合该学生当前水平。

- 例如：「该学生已 3 次遇到锁存器推断，本次直接 L2 起步」，或「已掌握组合逻辑，提示可更简洁」。
- 存储：SQLite（结构化轨迹） + 向量（语义相似度，复用 RAG 的向量能力，可后置）。

### 4.3 能力三：课程 RAG 知识库

深度结合知名课程（PA、一生一芯）与 SigFlow 文档，构建 RAG 知识库，让 Agent 引导时给出**课程链接、章节跳转、权威引用**。

- 报错/提问 → 语义检索 → top-k 相关章节 + 链接。
- MVP 内置精选种子章节（可从现有 `ModeController::CourseMapping` 的 11 条「错误→PA 章节」映射起步），附可扩展抓取脚本。

## 5. 双分支与模式切换

以 **LangGraph 为编排引擎**，一个状态图 + 两个分支，按用户所选模式切换分支/工具/提示词。

| 分支 | 定位 | 状态 |
|------|------|------|
| **教学模式分支** | 独立教学工具链 + 引导工作流（L1-L4 + RAG + 学生画像） | **MVP 全实现** |
| **工程模式分支** | 复用 UCAgent 验证工作流 + MCP 工具，定制化拓展 | 后续（受 cocotb/picker 的 Windows VPI 障碍约束） |

切换机制：`sigflow.project` 的 `agent.mode`（teaching/engineering）→ 对齐现有 `ModeController` 的双版本（Edu/Pro）→ 传入 `RunnableConfig` → 条件路由。

> 模式映射：教学模式 = Edu 版 = 场景②；工程模式 = Pro 版 = 场景①。

## 6. 交互流程

端到端一次教学交互（学生跑综合 → 报错 → 被引导）：

```
学生点「综合」→ yosys 报 warning（锁存器推断）
        │
        ▼
学生在教学面板问「为什么有 warning？」（或 Agent 主动弹出引导）
        │
        ▼
Agent：读综合报告（MCP job.report）
        │  得到 JobReport.errors[]{code:"Latch", severity:"warning", summary:"..."}
        ▼
Agent：匹配错误模式库（确定性）+ 查学生画像（确定起始提示级）
        ▼
Agent：RAG 检索相关知识点（组合逻辑完备性 / PA 章节）
        ▼
Agent：LLM 生成 L1 引导（方向性提问，不给答案）
        ▼
教学面板展示：L1 提示 + 课程链接 + [更进一步的提示]
        │
        ▼
学生继续/放弃 → 确定性引擎决定是否升 L2/L3/L4
        │
        ▼
交互结束 → 写学习历史（SQLite）→ 影响下次提示
```

关键边界（对齐 SigFlow_Plan_0907 §3.1.3「AI 三件事」）：Agent 负责**输入参数解读、结果解读、生成决策卡/引导**；**不直接执行工具、不替代学生做阶段决策、不直接改学生代码**。

## 7. 产品边界（非目标）

MVP 明确**不做**：

| 非目标 | 说明 | 后续 |
|--------|------|------|
| 直接改学生代码 / 一键修复 | 教学版不给答案 | 工程版分支 |
| 自动跑工具 | AI 不直接执行工具 | 可复跑/演示留接口 |

| 多课程全量适配 | 先 PA + 一生一芯种子 | 逐步扩充 |
| 教学效果评估系统 | — | v2 |

## 8. 验收标准

### 8.1 MVP 验收（教学版）

| # | 验收条件 | 对齐 |
|---|---------|------|
| AC-1 | 含锁存器推断的迷你工程，综合后 Agent 输出 **L1 方向性提问**，不直接给答案 | D-04 ② |
| AC-2 | 学生连续请求，Agent 沿 **L1→L2→L3** 逐步缩小范围 | D-06 |
| AC-3 | **L4 参考解法需二次确认**才展示；且只有门控允许的错误类型能到 L4 | D-06 |
| AC-4 | 引导中给出 **PA/一生一芯 课程链接**，可跳转 | 能力三 |
| AC-5 | 交互写入**学习历史**，再次遇到同类错误时**起始提示级变化**（个性化） | 能力二 |
| AC-6 | Agent 作为**独立进程**运行，**不阻塞 IDE 主线程** | 异步 |
| AC-7 | `enable_llm_agent=false` 时，现有确定性诊断层行为**不受影响** | 向后兼容 |

## 9. 术语表

| 术语 | 定义 |
|------|------|
| **Agent** | LLM 驱动的自主程序：感知上下文 → 决策 → 调用工具 → 生成回应 |
| **LangGraph** | LangChain 生态的图编排引擎，用状态图组织 Agent 流程 |
| **MCP** | Model Context Protocol，LLM 与外部工具之间的标准协议（JSON-RPC 2.0） |
| **RAG** | Retrieval-Augmented Generation，检索 + 生成：先从知识库检索相关内容，再让 LLM 基于它回答 |
| **sidecar** | 与主程序并列运行的辅助进程（本项目的 Python Agent 进程） |
| **L1-L4** | 四级教学提示：方向性提问 → 缩小范围 → 具体线索 → 参考解法（需二次确认） |
| **教学模式 / 工程模式** | Edu 版 / Pro 版：前者引导不给答案，后者精炼诊断 + 一键修复 |
| **确定性诊断层** | 不依赖 LLM 的纯代码解析器（NextpnrLogParser 等），100% 可复现 |

---

> **一句话灵魂**：**「识别错误」交给确定性的代码（已存在），「如何引导学习」交给 LLM——用 L1-L4 分级提示保证「引导而非给答案」。**
