# SigFlow × 高云：竞赛与科研合作沟通建议

> 文档版本：v1.0  
> 适用场景：EDA 项目竞赛、校企合作、科研立项、国产 FPGA 生态建设  
> 项目：SigFlow FPGA 集成开发与软硬件联合调试平台

## 1. 沟通目标

SigFlow 已经围绕 Verilog/电路图双向协同、Yosys/nextpnr FPGA 流程、TraceBridge 片上逻辑分析与波形回放，形成了从 RTL 到 FPGA 上板、再从实板采集波形回到 IDE 的完整技术路线。

我们希望与高云建立以**真实适配、联合验证、教学推广和科研共建**为核心的合作，而不是单纯申请板卡或寻求品牌背书。合作成果应能形成可演示、可复现、可量化的交付物：

- 在高云 FPGA 器件和开发板上跑通 SigFlow 的综合、布局布线、打包、下载和硬件调试闭环；
- 把高云器件的资源、时序、约束和调试特性转化为更适合学生与工程师使用的可视化体验；
- 沉淀可公开的示例工程、测试报告、课程案例、论文/专利/竞赛材料和生态反馈；
- 探索面向国产 FPGA 的新型 EDA 交互、设计理解和软硬件协同调试方法。

## 2. 项目现状与合作基础

SigFlow 当前具备以下基础，可作为第一次沟通时的项目证明材料：

| 方向 | 已有基础 | 与高云合作的结合点 |
| --- | --- | --- |
| 设计入口 | Verilog 与结构化电路图双向同步，维护 SFTree 语义结构 | 增加高云器件约束、资源和 IP 的可视化表达 |
| FPGA 流程 | Yosys 综合 Job、nextpnr 基础流程、Apicula/gowin_pack 打包、openFPGALoader 下载 | 形成高云器件的官方工具链/开源工具链双路径验证 |
| 硬件调试 | 自研轻量 ILA、UART/COBS/CRC 调试协议、TraceBridge 采集与 VCD 输出 | 与高云板卡建立稳定的采集、下载和调试适配基线 |
| 结果分析 | 仿真与实测波形对齐、差异定位、输入重放、资源及时序报告 | 反馈高云器件的综合、布局布线和调试使用体验 |
| 产品方向 | SigFlow Edu 教育版、SigFlow Pro 工程版，共享同一底座 | 对接高校课程、竞赛训练和工程试用场景 |

当前已有 Tang Nano 9K 的端到端验证经验。下一步可将高云官方器件、板卡和工具链纳入统一适配框架，并以高云平台作为国产 FPGA 适配的重点样板。

## 3. 建议向高云提出的支持事项

以下事项按优先级排列。第一次接触时建议先提出“核心支持包”，待双方确认合作意愿后再讨论扩展事项。

### 3.1 核心支持包：尽快拿到可验证的技术闭环

#### A. 器件与开发板支持

希望高云根据 SigFlow 的目标场景，推荐并提供 1–2 套适合教学、竞赛和调试演示的开发板，优先考虑：

- 具有稳定 USB/JTAG 下载链路和串口通道；
- 具备 LED、按键、时钟、DDR/BRAM、PLL、高速接口等典型外设；
- 器件规模覆盖“入门教学”和“有一定规模的工程验证”两类场景；
- 能够长期供货，便于形成公开教程、竞赛赛题和复现实验。

同时希望获得必要的转接线、下载器、调试附件及少量备份板卡，避免单板故障中断验收。

#### B. 官方工具链与器件资料

请高云提供或指引获取在授权范围内可用于科研和竞赛的资料：

- 对应器件和开发板的 Gowin EDA 版本、安装包、命令行接口和批处理使用说明；
- 器件型号、封装、时钟、IO、电气属性、BRAM/DSP/PLL 等资源资料；
- 管脚约束、时序约束、区域约束、差分 IO 和时钟专用资源的规则说明；
- 综合、布局布线、打包、下载及报告文件格式中适合程序化读取的字段；
- 可公开使用的示例工程、参考设计、IP 使用说明和常见错误案例；
- 对外发布时可使用的工具版本、器件名称、Logo 和截图规范。

我们的目标不是索取未公开的商业机密，而是获得足以完成**合法、可复现、可审计适配**的公开资料与授权边界说明。

#### C. 技术接口人和联合调试

希望高云安排一名 FPGA 工具链/器件应用技术接口人，在适配期提供定期答疑，重点协助：

- 解释官方工具与 Yosys/nextpnr/Apicula 路径在网表、约束、器件数据库和位流阶段的差异；
- 定位 SigFlow 在高云器件上的综合、P&R、打包、下载和时序异常；
- 协助确认器件资源统计、时钟使用、IO 规则和报错信息的正确解释；
- 讨论 TraceBridge/ILA 类调试方案与高云现有片上调试能力的边界和互补方式；
- 在关键里程碑安排一次线上或线下联合验收。

建议支持方式为每两周一次技术同步，问题通过共享清单跟踪，重大问题约定响应时限，而不是依赖零散即时沟通。

### 3.2 重点支持包：把适配做成竞赛和科研成果

#### D. 适配授权与合作边界

希望高云明确并书面确认：

- SigFlow 是否可以调用、封装或适配官方命令行工具；
- 是否可以在竞赛答辩、论文、开源仓库和公开演示中展示适配结果；
- 哪些器件数据、工具文件和日志可以随示例工程分发，哪些只能由用户自行安装；
- 是否可以发布“高云 FPGA 适配版 SigFlow”或仅能表述为“支持高云 FPGA”；
- 商标、Logo、软件许可、第三方组件和开源协议的使用要求；
- 研究成果、改进补丁、测试数据和联合署名的归属及发表流程。

#### E. 竞赛资源与场景支持

如果高云有高校合作或赛事资源，希望探讨：

- 将 SigFlow 纳入高云 FPGA 相关竞赛的辅助工具、参考开发环境或展示项目；
- 提供竞赛板卡、样片、训练营技术支持和官方技术讲座；
- 共同设计一套从 RTL、仿真、综合、上板到波形分析的可复现实训题；
- 为评审提供公开的技术指标和演示脚本，降低参赛队伍环境配置成本；
- 在高云高校生态活动中安排 SigFlow 联合演示或体验环节。

#### F. 科研合作方向

双方可以围绕以下题目形成联合研究，而不局限于工具适配：

1. 面向国产 FPGA 的图形—RTL 双向可逆编辑与设计中间表示；
2. 面向 FPGA 的综合、布局布线结果可解释化与设计空间探索；
3. 基于仿真—实测波形对齐的软硬件联合调试和根因定位；
4. 面向高校教学的数字电路四视图联动与分级错误提示；
5. 国产 FPGA 生态下的开源 EDA 与商业工具协同工作流；
6. 在可审计上下文约束下使用 AI 辅助理解 RTL、报告和波形。

科研合作可以从联合技术报告或学生创新项目开始，成熟后再申请产学研项目、发表论文、申请专利或共建实验课程。

### 3.3 可选支持包：提高长期影响力

- 提供高云器件的长期技术路线和适配优先级建议；
- 邀请项目成员参加高云培训、开发者活动或应用交流；
- 推荐真实但经过脱敏的工程需求，帮助验证 SigFlow 在非玩具项目上的价值；
- 协助联系高校实验室、竞赛组织方和生态伙伴；
- 对达到验收标准的成果提供联合新闻稿、案例文章或官方渠道展示机会。

## 4. 我们可以为高云提供的价值

合作不能只表述为“需要资源”，应明确我们能交付什么。

### 4.1 产品与技术价值

- **提供国产 FPGA 的新交互入口**：把器件、约束、综合报告、布局布线结果和硬件波形放进统一 IDE，降低初学者和跨工具用户的学习成本；
- **提供独立的用户体验反馈**：从学生、竞赛队伍和开源 EDA 用户角度记录工具链易用性、报错可理解性、上板稳定性和调试效率；
- **补充软硬件调试能力**：TraceBridge 可作为轻量、可追溯、跨工具的调试实验平台，与官方工具形成互补，尤其适合教学和科研验证；
- **沉淀适配层和自动化测试**：将器件 profile、约束检查、工具运行、报告解析和示例工程纳入可重复的回归体系，减少后续适配维护成本；
- **探索开源生态连接**：在许可允许的范围内，将高云平台接入更广泛的开源 EDA 和教学工具工作流。

### 4.2 生态与人才价值

- 产出面向高校的高云 FPGA 教学案例、实验指导和公开演示；
- 培养熟悉 FPGA、EDA、工具链和软硬件调试的学生开发者；
- 通过竞赛和科研项目为高云发现、吸引和提前培养 FPGA/EDA 人才；
- 形成可供其他高校和开发者复用的最小工程、验收脚本和问题知识库；
- 在论文、专利、竞赛答辩、技术报告和公开演示中规范体现高云平台支持。

### 4.3 可量化的合作交付

我们建议承诺以下可验收成果，具体数字可根据板卡和资料到位时间调整：

| 交付物 | 建议内容 |
| --- | --- |
| 器件适配 | 完成至少 1 个高云器件/开发板 profile，覆盖工程创建、约束、综合、P&R、打包和下载 |
| 示例工程 | 3–5 个由简单到复杂的 RTL/上板/调试案例，包含一键或半自动复现实验说明 |
| 流程验证 | 形成官方工具链路径与开源工具路径的结果对照，包括资源、时序、位流和波形证据 |
| 调试演示 | 在真实高云板卡完成 TraceBridge 采集、VCD 导出、仿真—实测对比和异常定位演示 |
| 测试报告 | 提交版本、器件、工具、约束、输入、输出、日志摘要和已知限制均可追溯的报告 |
| 教学/竞赛材料 | 提供至少 1 套实验或竞赛演示脚本，以及环境准备、常见问题和评分/验收标准 |
| 反馈闭环 | 按问题严重度提交适配问题清单和改进建议，必要时提供最小复现工程 |

## 5. 建议的合作分阶段方案

### 阶段一：技术摸底与资料确认（1–2 周）

- 双方确认目标器件、板卡、工具版本和授权边界；
- 高云提供开发板、工具和资料清单；
- SigFlow 提交最小适配工程、当前架构说明和测试方法；
- 共同确定第一个验收用例及双方接口人。

**阶段产出**：适配范围表、问题清单、环境基线、合作备忘录或邮件确认。

### 阶段二：最小闭环适配（2–4 周）

- 完成高云 target profile、约束样例和工具调用适配；
- 跑通 RTL → 综合 → P&R → 打包 → 下载；
- 建立资源/时序报告解析和产物指纹记录；
- 对关键失败场景形成最小复现。

**阶段产出**：最小可运行工程、适配补丁、自动化/半自动化验收脚本、阶段报告。

### 阶段三：TraceBridge 与联合调试（4–8 周）

- 在高云板卡上验证时钟、复位、UART/JTAG、采集和位流匹配；
- 完成硬件波形采集、VCD 加载、仿真/实测对齐和差异定位；
- 对比官方片上调试能力，明确互补场景和性能边界；
- 形成一次可公开演示的完整流程。

**阶段产出**：联合演示视频或现场演示、完整测试报告、已知限制和下一版路线图。

### 阶段四：竞赛与科研推广（按项目周期）

- 共建课程实验、竞赛题目或训练营案例；
- 整理论文、专利、项目申报和技术白皮书素材；
- 发布经双方确认的案例文章或生态展示；
- 根据反馈扩展器件、板卡和工具链支持范围。

## 6. 首次会议建议议程

1. 用 5 分钟介绍 SigFlow 的定位、当前成果和目标用户；
2. 用 10 分钟演示“RTL → 高云 FPGA → 采集波形 → 回到 IDE 分析”的目标闭环；
3. 用 10 分钟确认高云推荐的器件、板卡和工具版本；
4. 用 10 分钟讨论资料、授权、技术接口人和问题响应机制；
5. 用 10 分钟确定第一个最小验收用例、时间表和双方联系人；
6. 会后输出一页合作范围确认单，避免后续对支持内容理解不一致。

### 建议现场演示用例

优先演示一个结构简单但证据链完整的案例：LED 计数器或 UART 状态机。演示应包含：

- RTL 与结构视图的对应关系；
- 综合资源和布局布线报告；
- 高云板卡下载；
- TraceBridge 采样和 VCD 加载；
- 仿真波形与实测波形对齐；
- 故意制造一个错误，并展示定位到 RTL/信号的过程。

不要在首次会议承诺“替代高云官方 EDA”或“立即支持所有器件”。更稳妥的表述是：**SigFlow 是面向国产 FPGA 的统一交互与验证层，优先与高云工具链协同，并用可复现证据验证适配质量。**

## 8. 风险、边界与谈判原则

- **工具许可**：未获得书面许可前，不分发高云商业工具、器件数据库或受限文件；优先采用“SigFlow 适配层 + 用户自行安装官方工具”的分发方式。
- **开源边界**：对高云专有部分只提交接口、配置和必要的适配代码；对通用算法、测试框架和文档尽量保持可审计、可复现。
- **成果归属**：提前约定代码、问题报告、测试数据、论文、专利和宣传材料的署名及发布流程。
- **产品定位**：SigFlow 当前是竞赛/科研项目和生态工具，不承诺替代官方 IDE，也不对未获官方确认的器件特性作结论。
- **版本锁定**：每次验收记录 SigFlow、工具、器件、板卡、约束和位流哈希，避免“同一工程不同环境结果不同”。
- **技术承诺**：把“板卡和资料支持”与“高云内部修复工具问题”区分开；对后者使用问题单和明确优先级管理。
- **硬件安全**：下载、擦写和调试操作保留人工确认，不让自动化或 AI 直接替用户执行高风险操作。

我们向高云提出的核心诉求是：**板卡与资料、合法的工具链适配条件、稳定的技术接口和真实的联合验证场景**；我们能提供的核心价值是：**一个可复现的国产 FPGA 统一开发/调试入口、一套面向高校和竞赛的案例与人才触达渠道，以及持续、结构化、可落地的工具链反馈**。
