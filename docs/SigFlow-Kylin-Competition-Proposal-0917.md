# 企业命题：芯创麒麟

> 「芯创麒麟」——面向国产操作系统的开源 FPGA 全流程 EDA 环境轻量化适配与产教协同实训平台
>
> **命题组别**：企业命题组 — 产教协同创新组
> **命题类别**：新工科 / 集成电路与信创软件
> **出题单位**：SigFlow 项目组（数字逻辑设计集成开发平台）
> **版本**：v1.0 · 2026-09-17

---

## 一、命题背景

集成电路设计工具（EDA）长期由国外厂商闭源垄断，其工具链无法在国产操作系统与国产 CPU 平台上自由部署、审计与教学分发。近年来，以 Yosys（综合）、nextpnr（布局布线）、Apicula（比特流打包）、openFPGALoader（下载烧录）、Verilator（仿真）为代表的开源 FPGA 工具链，已经覆盖了多家国产 FPGA 厂商从 RTL 到上板的完整流程，为构建自主可控的 EDA 软件栈提供了现实基础。然而这批工具以碎片化命令行的形式存在，缺乏统一的集成开发环境、任务化执行框架与软硬件联合调试闭环，在国产操作系统上的适配、分发与教学落地均缺乏系统验证。

与此同时，高校数字电路与 FPGA 课程的实验环境正在快速向国产化迁移。大量院校的信创机房已装配麒麟操作系统，但实验课上"系统装好了、工具跑不起来"的现象普遍存在：教师需要在数十台国产系统机器上重复配置环境，学生缺少可在国产平台上完整复现"写代码—看波形—上板跑"的实训路径，教材与实验指导书中的案例又大多绑定国外闭源工具。国产操作系统在高校的推广，最终卡在了"没有一个可用的专业工具环境"这一环。

SigFlow 项目组此前已完成面向数字逻辑设计的集成开发环境建设，形成了从 Verilog 代码、结构化电路图、仿真波形到 FPGA 上板流程的可交互闭环：工程内已跑通 Yosys 综合、nextpnr 布局布线、Apicula 打包与 openFPGALoader 烧录的任务化执行，并自主实现了轻量片上逻辑分析（TraceBridge）的软硬件联合调试链路——串口采集、协议解码、波形回放、仿真与实测双轨比对均已通过实板验收。在此基础上本命题要求参赛团队进一步面向麒麟操作系统完成全流程环境的轻量化适配与产教协同转化，形成可运行、可验证、可推广、可进课堂的国产平台 FPGA 开发与实训环境。

## 二、命题内容

参赛团队需基于麒麟操作系统（openKylin / 银河麒麟）及相关技术底座，完成开源 FPGA 全流程开发环境的适配、轻量化与产教转化，并在真实教学场景中完成验证。参赛团队应重点完成以下内容：

**1. 分析开源 FPGA 工具链的适配需求，完成工具链的裁剪、整合与轻量化分发。** 逐一分析综合、布局布线、打包、烧录、仿真各组件在国产操作系统上的依赖关系与运行特征，对工具链及其运行时资源进行合理裁剪与配置，形成可一键部署的工具链运行时，降低安装体积与运行资源占用，并优化系统启动、工程加载与首次综合的开销。

**2. 构建统一的任务化执行框架，保障典型工程在国产平台上跑通全流程。** 将碎片化的命令行工具封装为具备状态机、异步执行、结构化报告、取消与超时治理、产物可回溯的任务对象，使"RTL → 综合 → 布局布线 → 打包 → 比特流 → 上板"在麒麟平台上全程不依赖任何闭源工具与 Windows 环境即可完成，并保证每个环节的输入、日志、产物与状态可保存、可复现、可重试。

**3. 构建软硬件联合调试闭环，并选定一种典型任务完成端到端验证。** 通过串口/USB 通道实现板端信号采集、协议解码、波形呈现，以及与仿真波形的对齐与差异定位；在信号采集、协议解码、状态机异常检测、显示输出等典型任务中选定一种，完成从设计、综合、上板到回读分析的完整闭环演示。

**4. 将适配成果转化为高校可用的实训资源包，并完成一次真实教学场景的试用闭环。** 面向数字电路/FPGA 课程的实际教学需求，沉淀示例工程、实验指导材料与典型错误模式库；对学生在设计过程中的常见错误（组合环、锁存器推断、位宽不匹配等）提供分级提示机制，引导学生自行定位问题而非直接给出答案；在信创机房、暑期学校、竞赛训练营或课程实验等真实场景中完成小规模试用，回收师生反馈并给出迭代说明。

**加分项（在完成上述内容的基础上进一步开展）：** 面向国产 CPU 多架构环境，重点突破工具链跨架构编译适配、平台抽象层统一、多架构构建分发等关键技术，覆盖 ARM64（飞腾/鲲鹏）等架构，并鼓励向 LoongArch（龙芯）等架构延伸验证；同时鼓励结合综合与布局布线报告、波形数据开展 AI 辅助的设计错误根因分析与调试建议生成。

## 三、考核维度与评测要点

| 维度 | 评测要点 |
|---|---|
| 平台覆盖 | 麒麟 x86_64 为必选基线；ARM64 麒麟为加分项；LoongArch 等其他架构显著加分 |
| 全流程贯通 | 指定示例工程在麒麟平台上"综合→布局布线→打包→烧录→采集回读"全流程成功率 100%，全程无闭源工具依赖 |
| 轻量化程度 | 可一键部署运行时的体积上限、空闲内存占用、工程加载与首次综合耗时等指标的实测数据与优化说明 |
| 任务化完备度 | 完成封装的任务类型数量（建议不少于 4 类），每类具备状态机、结构化报告、取消/超时与产物落盘能力 |
| 调试闭环质量 | 板端采集数据能够正确解码并在波形视图中呈现，可与仿真波形对齐比对，差异定位结论可复现 |
| 产教转化质量 | 实训资源包的完整度（示例工程、实验讲义、错误模式库、分级提示规则），以及真实教学场景试用记录与师生反馈闭环 |
| 工程规范性 | 构建脚本、验收脚本、CI 门禁、文档的完整性与可移交性，第三方可在干净环境中依据文档独立复现 |

---

## 四、交付物要求

1. **可一键部署的国产平台运行环境**：包含工具链运行时、集成开发环境与安装/卸载脚本，并在目标麒麟机器上完成实测；
2. **全部源码与跨平台构建脚本**：构建流程需可在干净环境中依据文档独立复现，配套自动化验收脚本与 CI 配置；
3. **示例工程与验收报告**：至少一个完整示例工程的全流程运行记录、产物清单与实测数据（资源、时序、采集波形）；
4. **实训资源包**：课程案例、实验指导材料、典型错误模式库与分级提示规则说明；
5. **试用与反馈材料**：真实教学场景的试用过程记录、师生反馈汇总与后续迭代说明；
6. **现场演示与答辩**：在全流程演示中至少展示一次由 RTL 修改到重新上板采集的完整回环。
