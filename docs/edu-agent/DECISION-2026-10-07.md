# SigFlow Agent 自研决策（2026-10-07）

## 决策

教学版与后续工程版只参考 UCAgent 的可取架构思想，例如分阶段工作流、受限工具、阶段检查和运行记录。SigFlow 团队自行设计、实现并维护 Agent；交付物不依赖 UCAgent 源码、运行时、`UCTool`/`Checker` 类、默认验证流程或上游镜像。可以借鉴思想，不复制代码或把上游名称用作本产品接口契约。

一期只交付 **SigFlow Edu 教学 Agent**。工程版的目标、权限、工具和验收在后续独立规格中定义；教育版不得因为预留工程版而开放自动改 RTL、布局布线、打包、烧录或任意命令执行。

一期沿用现有工程边界：C++ SigFlow 掌握工程、EDA Job、报告、波形、执行授权和原生 UI；自研 Python 教学服务负责教学流程、提示策略、课程与学习记录。双方通过本机、认证的 HTTP 契约通信。选择 Python 是本期实现决定，不来自 UCAgent 依赖要求；Windows x64 与 Linux x64 的原生安装和端到端运行仍需实测。若后续改变语言或部署形态，须先修订双方规格和验收。

Docker 镜像、容器启动器和统一远端服务均为**按目标用户需求评估的可选部署方案**，不是教学版一期发布门槛，也不能替代原生 Windows/Linux 的验收记录。后续决定采用容器时，单独验证目标电脑的虚拟化、网络、资源、安装权限及 SigFlow 与容器的受控通信。

## 保留的产品与安全约束

- 教学 Agent 以可追溯的工程快照、诊断、报告、波形和课程资料为依据；观察、假设和验证结论分开表达。
- L1–L3 逐级引导；L4 需策略允许及两次真实用户操作。学生自行改代码，Agent 不代写工程文件。
- 仅可通过 SigFlow 授权接口申请教学范围内的仿真与综合；SigFlow 是 EDA 执行与结果的事实来源。
- 工具调用采用显式白名单、类型校验、授权、幂等、预算、审计和失败即停。模型不能签发凭据或任意扩展工具权限。
- Agent 不可用时，SigFlow 的编辑、手动仿真和综合仍可使用。
- 教学版与工程版可共享基础设施，但 edition 和 policy 必须在服务端执行边界校验，不能仅依赖界面隐藏。

## 文档与验收迁移

以 `docs/edu-agent/{sigflow,ucagent}/{spec,task}.md`、`docs/edu-agent/Cooperate.md` 和 `contracts/edu-agent/v1/` 为当前实施资料。`ucagent/` 是既有目录名，**不表示继续使用 UCAgent 实现**；后续目录迁移须连同所有相对链接和 CI 路径一起执行。历史规划文档仅作背景，以本决策及同步修订后的实施规格为准。

保留已有 SigFlow Gateway、Job、快照、报告、授权和 sidecar 的实现与进度记录。Agent 组原有“固定上游、上游兼容补丁、真实 UCAgent trace”验收项作废，改为自研工作流、受限工具、证据检查、跨平台服务和教学效果的实际运行证据。工作量、负责人和十周 Gate 以重新估算后的 task 为准，不能机械沿用旧人日。
