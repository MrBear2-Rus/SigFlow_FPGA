非 GUI 底座已经能提供本地 HTTP Gateway、工程快照、授权、Job 提交、报告与波形查询的基础接口。第一轮补齐了报告可信绑定、计划步骤授权、Job 绑定恢复、真实 VCD 注册和 Windows Git shell 发现；第二轮补齐了 NG-05 的 Gateway/核心侧、NG-07/08/09 的主要实现。**第四轮还修正了 NG-07 的两个发布级缺口：Windows 宿主会通过 `cmd.exe` 真实承载 `.cmd/.bat` 启动器；模型文本进入卡片前会拒绝本机路径、当前进程密钥、代码块/Verilog 形式和超长响应，再降级为规则卡。**

## WSL(POSIX) 补充验证（2026-10-08，**不替代原生 Linux 验收**）

在 WSL2 / Ubuntu 22.04.5（x86_64，g++ 11.4，cmake 3.22，python3 3.10）上做的额外验证。
按本清单"明确禁止的边界"，**WSL 不是原生 Linux 验收**：它的互操作层能执行 Windows PE
二进制，会把"Windows 工具"冒充成 Linux 结果。因此下面只作补充证据，平台矩阵仍为阻塞。

**已实测通过**

- 真实 CMake 配置成功（离线：`-DSIGFLOW_ALLOW_FETCH=OFF -DSIGFLOW_FETCH_WX=OFF
  -DSIGFLOW_USE_LOCAL_WX=ON -DSIGFLOW_BUILD_EDU_AGENT=ON -DSIGFLOW_BUILD_TESTS=ON`），并在
  Linux 上成功构建 Gateway 核心的 12 个目标（含本轮新增的 `DesignContextService` /
  `LegacyJobBridge` / `PathRedaction` / `SchemaRegistry` 改动）以及 `wxbase`。
- `ctest -R edu_` 在 Linux 上 **12/13 通过**（唯一失败见下方缺口）。其中
  `edu_agent_sidecar_smoke` **通过**：真实 Python sidecar 与 `AgentServiceController`
  在 Linux 上完成 bootstrap→ready→health→卡片→shutdown，含双实例隔离。
- `edu_schema_runtime_smoke` 在 Linux 上通过，并实测 POSIX 分支的路径编码：
  "UTF-8 project name round-trips through filesystem path"、
  "UTF-8 non-BMP path component round-trips"、
  "UTF-8 project directory is created at its round-trip path"。
- 自研 sidecar 在 WSL：`run_all.py` **110/110**、`verify_install.py` **ALL PASS**、
  **POSIX 启动器** `agent/bin/sigflow-edu-agent` 端到端 **ALL PASS**（ready 的 nonce/端口/版本、
  health 协议、错 token 401、shutdown 202、退出码 0、日志不含 token），并确认它遵守
  `SIGFLOW_EDU_AGENT_PYTHON`。这是该 POSIX 启动器第一次被真正执行。

**顺带修掉的验证资产缺口**：`edu_real_tool_smoke` 原本硬编码查找 `yosys.exe` /
`verilator_bin.exe`，于是（1）在**原生 Linux 上永远只会 SKIP**——等于 Linux 侧没有真实验收；
（2）在 WSL 上被互操作"骗"着去跑 Windows PE 二进制，得到假失败。现在按平台解析：
Windows 仍用仓库随附 runtime，**POSIX 只用系统 PATH 上的原生工具**（仓库随附 runtime 是
Windows 载荷，还包含指向 `.exe` 的包装脚本）。Windows 行为不变（`ALL PASS (skipped=0)`）。

### WSL 验证发现的缺口（未修，需产品决策）

`edu_real_tool_smoke` 在 Linux 上稳定复现 1 条失败：

```text
  ok: capabilities readable
  FAIL: missing yosys is reported as not ready (no fake capability)
  SKIP: real yosys not present: synthesis end-to-end not exercised
```

即**工具不存在**时，`GET /capabilities` 仍把 `eda.synth` 报为 `ready=true`。原因是能力就绪
口径只取"插件/provider 已注册"（`Composer::ReadyPlugins()` 与测试里的 `ReadyPlugin` 列表同
口径），没有把"工具是否可解析"算进去。这与该测试与 spec 的期望（"能力来自真实 ready 状态，
缺失理由可读，不能只看插件文件存在"）不一致，也与 NG-07 验收里"工具未装"应是独立状态相呼应。
Windows 上因随附工具存在，该断言被跳过，所以只在缺工具的环境暴露。修它需要把工具可用性接进
宿主的能力上报（`MainFrame` 侧装配），属产品行为变更，本轮只记录、不改。

  双工程并发只读压力）。
- **修掉一个真实的偶发缺陷（不是测试问题）**：`edu_event_retention_smoke` 约 5% 的运行会在
  **第一次**建快照时拿到 `503 SERVICE_UNAVAILABLE / unable to commit snapshot directory`。
  根因是 Windows 上"刚写完文件的目录 rename"会被防病毒/搜索索引器短暂持有
  （sharing violation / access denied），而提交路径只 rename 一次、失败即报 503。
  已在 `SnapshotService` 加入**有界退避重试**（约 150 ms，失败原因仍如实上报）。
  验证：修复前 60 次运行 3 次失败 → 修复后 60/60 通过，`edu_snapshot_grant_smoke` 10/10，
  `edu_` 全绿连续 3 轮。这是真实用户（装了杀毒软件）也会遇到的故障，不只是测试抖动。
- **修掉一个真实的红色测试（非 GUI）**：`eda_sim_verilator_smoke` 的三条断言一直在失败。
  根因不是插件缺陷，而是测试的前置条件过期——它只在 `--binary` 出现在参数里时才记录构建调用，
  而插件在 10-07 已刻意改成显式 `--cc --exe --build --trace`（`--binary` 会强制加入 Verilator
  自带的 `--main`，与受控 trace main 冲突且不产 VCD）。测试改为按 `--build`（兼容 `--binary`）
  判定后全绿；插件与契约未改。
- **`job_tests` 的唯一失败已定性为环境限制**：受限沙箱里 `LocalPipe::CreatePair` 打不开 Windows
  命名管道（lastError=5 拒绝访问）；用完全权限跑同一个可执行文件得到 `ALL TESTS PASSED`
  （86/86 断言）。因此这不是代码回归，而是本会话沙箱的已知边界。

  1. 真实 Verilator 报告把 `g++`/`make`/`python3`/`verilator` 的**本机绝对路径**放进 `metrics.preflight.value`，直接暴露给 Agent。现在结构化路径统一裁成文件名并显式标记（`path_redacted`/`file_redacted`）。
  2. **中文/非 ASCII 相对路径此前完全不可用**：`core/src/eda-core/Project.cpp` 用 `std::filesystem::path(utf8_string)` 构造路径，Windows/MinGW 下会把每个字节当成一个宽字符，工程因此报 "registered project source is unavailable"；`GatewayServer` 的 `/sources/{id}` 与 `/context/query` 也用了同样的写法，返回 410。已改为 `platform::PathFromUtf8`。
  3. `generic_string()` 双重编码：新增 `platform::RelativePathToUtf8()`（UTF-8 + POSIX 分隔符），替换 `PathToUtf8(path.generic_string())`（`GatewayServer` 源摘要、`SnapshotService` 清单）。
  - 断言在 `edu_report_normalizer_smoke`、`edu_design_context_smoke` 与 `edu_schema_runtime_smoke` 内；`edu_schema_runtime_smoke` 现在实测"UTF-8 非 ASCII 源路径可加载 + `/sources/{id}` 可读"。
  - 兼容性提示：非 ASCII 路径过去无法加载，因此不存在"旧快照用了双重编码路径"的可用数据；ASCII 路径的清单表示不变（本来就是正斜杠）。
- **契约与文档**：`sigflow.openapi.yaml` 新增 design-node 与 legacy 路由、扩展 `/context/query` 语义、纠正已过时的"报告未回填 project/revision"偏差说明；`CHANGELOG.md` 增加本轮条目。
