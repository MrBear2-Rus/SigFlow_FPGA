## 1. 先说结论

需要调整，但**不用推倒 SigFlow 非 GUI 底座重做**。工程快照、Gateway、授权、Job、报告归一化、波形查询等已有实现应继续复用。

当前最重要的变化是：Agent 实际交付的 `agent/` 是“创建会话 → 按次请求 → 返回教学卡片”的精简 sidecar，并不是原规格里的完整教学主控。它现在不能自动完成 E0–E7、逐级提示、真实 L4 确认、审批后执行计划、课程检索、学习记录和跨重启恢复。

本次分两层推进：

1. **A 阶段：接通现有服务。** 修启动与边界问题，补 SigFlow typed client、会话/卡片/事件适配，交付可靠的解释、提示、报告解读和只读计划建议。L4 与自动执行在安全闭环完成前关闭。
2. **B 阶段：兑现教学版规格。** 双方共同扩展教学动作、receipt 门控、受控执行、证据查询、课程与记录；这些不是画完教学面板就能自动获得的功能。

“A 阶段接通”不能写成“教育版全部完成”；也不能把 B 阶段全部归给 SigFlow UI。

下文的“接口 A/B”表示两个通信方向，“A/B 阶段”表示实施批次，二者不是同一概念。

## 2. 不变的架构和边界

### 2.1 架构不变

- 教学 Agent 自研，UCAgent 仅作架构参考；不重新引入 UCAgent 运行依赖。
- 教学版原生支持 Windows/Linux；Docker、远端统一服务、云端多租户仍不进入本轮。
- Python 负责证据理解、教学策略、卡片与验证建议。扩展受控执行后，Python 可以申请 Gateway Job，但不能自己运行 EDA 命令。
- C++ SigFlow 负责工程事实、不可变快照、能力与参数约束、可信用户操作、授权、EDA 进程、报告和波形。
- 学生自己修改 RTL。Agent 不写工程文件、不自动修复，不暴露教育版 pnr/pack/flash/debug 能力。
- Agent 故障只影响 Agent 功能，不影响原有编辑、New/Open、手动综合与仿真。

### 2.2 三个身份必须明确区分

| 身份 | 使用方和用途 | 不允许的用途 |
|---|---|---|
| UI → Agent token | SigFlow 内部客户端调用 Python 会话、run、事件、关闭接口 | 不作为 Gateway UI 身份，不进入模型或卡片 |
| Agent → Gateway token | Python 的受限客户端读取证据；后续按 grant 提交 Job | 不签发/撤销 grant，不签发 receipt |
| Gateway UI token | SigFlow 可信交互控制器签发/撤销 grant、签发 receipt | 不传给 Python，不进入启动 JSON、网页脚本、模型或工程文件 |

不要因为名称都含 `ui_token` 就共用一个值。bootstrap 中的 `ui_token` 是第一类，不是第三类。

### 2.3 本轮明确不做

不重构现有 JobService/插件体系；不开发工程版；不引入任意 shell、通用文件工具或自动改码；不把本轮扩展成教师后台或云服务。原有手动烧录/调试照常保留，但不开放给教育 Agent。

P0：在对应功能启用前必须解决。P1：A 阶段联调/后续教学闭环必需，但可通过关闭该入口控制首批范围。P2：后续增强。这里的优先级不替代旧 spec 的一期范围承诺。

| ID | 当前情况和风险 | 调整方向 | 责任/优先级 |
|---|---|---|---|
| AD-01 | 宿主 bootstrap 使用 JsonCpp 默认带缩进输出；Python 只读 stdin 第一行 | 显式单行 UTF-8 JSON，检查写入、大小和管道错误；补真实控制器测试 | S1 / P0 |

| AD-04 | Python 缺 Origin 校验；Gateway URL 只检查 scheme，urllib 默认重定向未被禁用 | 请求边界与出站地址白名单、拒绝重定向/代理绕行、凭据隔离 | U1/S1 / P0 |

| AD-06 | 同会话并发 run 在锁外预估 state_version，卡片与 run 版本可能不一致 | 每会话串行化/事务提交，事件与 run 原子关联；旧请求不写新会话 | U1/U2 / P0 |

| AD-10 | Agent 事件不长轮询、内存保留，单次读取有限；watermark 不等于本页消费位置 | A/B 两套订阅策略、去重与分页补读、失效恢复 | S1/U1 / P1 |
| AD-11 | Gateway 的底层图元/选择接口已有，真实 SigTree/Canvas 抽取还未接上 | 主线程生成不可变 DTO，后台只读；无映射明确 unavailable | S2/S3 / P1 |

| AD-13 | 64 位 tick 输入、空源码区间、错误枚举等存在已知偏差 | 专项兼容修订，保留明确的迁移规则与负例 | S1/U1 / P1 |

### 4.1 本次有直接证据的两个缺陷

- 用当前解析器构造**第一次** `kind=explain, level=L4, more=true` 请求，直接得到 `reference_solution` 卡片。该请求无需先前状态。当前卡片只是参考要点而非完整模块，但这仍证明“两次独立操作”未被服务端约束。
- 调用 `sufficient_report`，输入只有 `completeness=complete`、非空 revision 和空 diagnostics，**不提供 origin**，返回可信。该结果仅验证当前判断函数，不能推导整个 Gateway 已被越权。

启动格式问题的源码链也明确：`AgentServiceController::BootstrapPayload()` 使用默认 `StreamWriterBuilder`，本仓 JsonCpp 默认 indentation 为制表符；`bootstrap.read_from_stream()` 只调用一次 `readline()`。应修实际宿主，而非只修文档示例。

### 4.2 新版指南需要同步纠正的说法

1. `sidecar-bootstrap.md` 和双方 spec 在本仓存在，不能继续标为“仓库外未随附”。
2. Python 最低版本：指南写 3.11+，`pyproject.toml`/README 写 3.9+。建议先以 3.11/3.12 为本轮明确验收版本；是否继续承诺 3.9 由测试决定，不直接删兼容声明。
3. “GatewayClient 不跟随重定向”与当前 `urllib.request.urlopen` 实现不符。须实现禁止重定向并测试后再保留该说明。
4. “唯一出站通道”应改成“唯一工程/EDA 证据通道”；可选模型客户端本身也会访问外部端点。
5. L4 的 `more` 不是可信二次确认；必须改为“当前实现缺陷/暂禁用”，不能写成已完成安全能力。
6. A/B 的状态码、事件保留、长轮询、限额不能混成一张通用表；A 的 `error.details` 当前为 null，B 的响应超限可能带预算信息。
7. “取消路由不带 project，所以跨工程取消不可表达”不能作为安全结论。Job ID 可以指向其他已登记工程，客户端必须检查当前上下文，服务端须按产品定义验证归属/权限。
8. 工具自由文本路径脱敏在当前 C++ 已有进一步实现与测试；不要继续当成完全未做，应核对覆盖范围并补 Python 输出侧防御。
9. 接口 A 的 `capabilities.execution.can_run_eda=false` 是当前事实；不能把 Gateway 已可执行解释成 Python 已具备执行流程。

## 5. A 阶段：SigFlow 侧具体调整

### 5.1 sidecar 宿主与连接生命周期（AD-01/02/15）

修改 `main/agent/AgentServiceController.{h,cpp}`，保留现有 loopback、stdin 秘钥传递及 1/2/4 秒退避机制。

- bootstrap 使用紧凑 JSON，加且只加一个换行；UTF-8 字节总量不超过 64 KiB，不因中文路径增加物理行。检查 Write 的实际长度与错误状态，失败即停子进程并清空敏感缓冲。
- ready 必须完整单行，校验 type/protocol/nonce/port/version。端口由系统分配，不能从项目文件读取。
- 统一 stdout 规则：建议严格只允许 ready 一行，其余日志走 stderr；当前 bootstrap 文档允许 ready 前 stdout 日志，与新版指南冲突，需双方修改并补测试。不要在未协商时突然改变兼容行为。
- 先拿 ready，再验证标准 health 信封及 `ready=true`、instance_id、协议、版本一致，最后才进入业务可用状态。模型不可用不等于 sidecar 不健康。
- 新增内部连接描述：endpoint、协议、agent_version、IDE instance、sidecar generation、有效状态。token 只留受控客户端/连接对象内存，不放可打印 Status、普通事件、WebView 或日志。
- 每次重启递增 generation，轮换 UI→Agent token，原子替换客户端；旧 HTTP 回包、health future、退出回调不得影响新代次。
- stop 先失效业务连接，尝试认证 `/shutdown`，有界等待后再终止子进程树；取消后台请求，避免在 UI 线程无界等待。
- instance_id 改为随机高熵标识。当前按秒时间字符串不能保证同时打开两个 IDE 实例的唯一性。
- Gateway token 热轮换另做协议协商；当前不要把轮换 UI→Agent token 错写成撤销了旧 Agent→Gateway 权限。旧进程必须确实退出，旧审批不得自动继承。

完成条件：从真实 MainFrame/Controller 启动已安装 sidecar，解释卡可用；重复重启后旧 token/旧回包失效；关闭无残留；失配只禁用 Agent。

### 5.2 typed client 与 DTO（AD-07/08）

建议新增 `main/agent/AgentApiClient.*`、`AgentDtos.*`、`AgentSessionController.*`，名称可按仓库习惯调整，职责不可混入面板事件函数。

| 客户端方法 | 实际 A 路由 | 行为 |
|---|---|---|
| Health / Capabilities | `GET /api/v1/health`、`/capabilities` | 验证信封、版本和各功能真实状态 |
| CreateSession / GetSession | `POST /api/v1/sessions`、`GET /sessions/{sid}` | 绑定 project/revision/top/target/locale |
| CreateRun / GetRun | `POST /sessions/{sid}/runs`、`GET /runs/{rid}` | 四种 kind；成功当前为同步完成后的 201 |
| ReadEvents | `GET /sessions/{sid}/events?after=...` | 即时读取，不发送未定义的 wait_ms |
| Shutdown | `POST /api/v1/shutdown` | 认证、有界退出 |

所有路径均以 `/api/v1` 为前缀。对外调用在后台执行，返回 UI 线程更新视图；**同步 HTTP 语义不等于可以阻塞 UI 线程**。模型内部超时目前 30 秒，客户端总 deadline 应覆盖服务处理与必要余量；取消等待不代表服务器没有创建 run。

- 成功/失败信封分开解析，同时检查 HTTP 状态和领域码；保留 request_id/trace_id 供排障，输出中不含 token/绝对路径。
- 字段由 schema 解析，64 位 sequence/state_version/tick/size 不经过浮点数，使用十进制字符串和受检整数转换。
- TeachingCard 与 PlanCard 使用联合 DTO。**PlanCard 没有 `kind`**，不能按 `kind=plan` 判断；两类都不匹配/同时匹配则拒绝，不能执行不明卡片。
- 未知可选响应字段允许忽略；未知枚举显示 unsupported。安全敏感请求字段、计划参数不得用“忽略未知字段”处理。
- 单次最多 16 卡，完整响应设置字节预算；校验卡片非空 evidence/limitations、状态版本、ID 及字段类型。schema 本身不能代替内容安全与教学语义检查。
- 没有 Key 显示规则模式，`model_used=false` 不伪装为模型分析；`omitted` 展示省略原因。
- source/card/plan/run 等 ID 都按作用域缓存：至少包含 IDE instance、sidecar generation、project、session/run。尤其 `source_id` 不跨工程全局唯一，`card-1` 和 `plan-1` 会复用。

### 5.3 工程、会话、版本与过期（AD-05/06/10）

建议采用以下明确规则，避免 UI“看起来切换了”但请求仍落在旧工程。

| 事件 | 客户端必须做什么 |
|---|---|
| 打开/切换工程 | 读取 Gateway context，绑定 project/revision；新建或查找同代次对应 session，不沿用其他工程 session |
| 未保存编辑 | 标 dirty；选中缓冲可用于解释，注明未保存；禁止以它启动已保存快照执行 |
| 保存或外部修改使 revision 改变 | 当前 A 没有 session revision 更新接口，建立新 session；旧卡片本地标记“历史版本” |
| 切换 top/target/策略 | 重新获取 context 并更新会话绑定，不能只替换卡片标题 |
| sidecar 重启/更换版本 | 所有内存 session/run/cursor 失效；旧结果仅作历史展示；重新握手/建会话，不自动重复执行请求 |
| A 返回 session/run 404 | 区分 LRU 淘汰/重启与工程不存在；提示重新建立会话，不凭相同 ID 恢复 |
| 请求完成时已切工程 | 依据请求时的 project/revision/generation 投递历史记录或丢弃，不覆盖当前面板 |

注意：当前 TeachingCard schema 的 `expired` 为 `const false`。客户端的历史/失效状态是本地 view-model，不应把服务端 DTO 改成 `expired=true` 再声称符合现有契约。要让服务端发过期卡，须另行修订契约。

每个 session 在客户端先限制一个进行中的写请求；服务端仍须实现同样的串行/事务约束，不能依赖 UI 不并发。state_version 由服务端在提交时统一赋给 run、卡片和事件，不能在模型请求前锁外推算。

进行中的 session 应有 pin/lease，不能被 LRU 淘汰后继续向孤立对象写结果。网络/模型请求不持有全局 store 锁；提交时再次校验会话/代次，并以一次事务完成版本、run 与事件更新。

### 5.4 教学面板接入边界

首批面板可以提供：解释选中片段、请求提示、解读已选 Job 报告、查看验证计划建议、显示服务/模型状态、查看证据定位和失败原因。

- A 的 `hint(level=L2/L3)` 是一次请求的等级选择，**不是**已经实现“同 issue 逐级升一级”。严格教学模式的逐级入口待 B 阶段服务端动作完成后启用。
- 不出现可用的“L4 参考解”和“执行整个计划”入口；同时服务端必须拒绝，不能只把按钮隐藏。
- 不显示尚无 API 支持的 WaitingStudent、WaitingApproval、课程命中、个人学习画像或恢复成功状态。
- 卡片与错误消息按不可信内容呈现；HTML/Markdown 禁止脚本、事件属性和任意本地文件/外部协议链接。
- “定位源码/图元/波形”使用 opaque ID 和可信宿主映射；文本中的路径、命令、链接不能成为执行指令。
- 与旧 `Plugin_DeepSeek` 助手入口明确分开，避免一次操作调用两套模型或弹两份建议。

## 6. A 阶段：Agent/Gateway 配套修复

### 6.1 入站与出站安全（AD-03/04/07）

- L4 默认服务端失败关闭。capabilities、解析器、dispatcher、模型上下文及卡片输出保持一致，任何 kind/level 组合不能绕过。
- Python 检查 Host 和 Origin；拒绝非预期来源与通配 CORS。对 Host/端口采用完整解析，不靠字符串截取。是否允许本机浏览器 Origin，由可信 UI 部署方式决定并记录；loopback 不等于浏览器可信。
- bootstrap 的 Gateway URL 强制匹配本地受信地址/端口，不接受用户输入 URL、userinfo、任意路径或非 loopback 地址。
- GatewayClient 使用明确禁用代理、拒绝重定向的 opener；模型请求也不能将 Authorization 随重定向转发至其他端点。模型 endpoint 另设配置校验，不能复用 Gateway 白名单。
- 为请求 socket 设置读取/写入超时和并发/排队限额。当前 ThreadingHTTPServer 不能视为有界 worker 池。
- 请求体按 UTF-8 字节计算上限，验证 Content-Type/Content-Length；超大请求不能无期限阻塞在 drain 上。输出预算先于发送检查，不能截断半个 JSON。
- 安全参数严格验证类型、长度、数值范围；拒绝 bool 冒充整数、负数、极大 cursor、非法行区间、带路径的 ID。客户端与服务端均校验。
- token/Key 在日志、异常、health/model.provider、卡片和错误消息中均需脱敏；模型 endpoint 配置不得回显带凭据的 URL。

### 6.2 报告可信度与归属（AD-05）

`report_review` 不能只凭 job_id、非空 revision 或 diagnostics 数组判断可靠。

1. GatewayClient 验证成功信封、版本与 `JobReportView`；不把任意根 JSON 都当报告兼容接受。
2. 将 session 的 project_id/revision 传入证据校验流程；核对 report.job_id、project_id、revision、snapshot/input fingerprint 等实际绑定。跨工程结果不得生成当前工程卡片。
3. 严格按当前 schema 处理 origin/completeness：目前 origin 为 `core/legacy`，completeness 为 `complete/partial/unavailable/legacy_unverified`。Python 额外认可的 `gateway/exact` 不能当成冻结报告契约。
4. 运行中、取消、失败、缺字段、legacy、部分报告可以展示其真实诊断与限制，但不能形成“当前版本验证通过”的结论；空 diagnostics 缺失/格式错误不得当成正常空数组。
5. 即使 Succeeded + complete + 空 diagnostics，也只说明该工具本次检查没有报告相应问题，不证明全部功能或时序正确。
6. 旧 revision 的报告允许明确以历史视图展示；当前 A 请求没有“历史解读”模式时，先拒绝当前版解读，不能静默更换 session revision。
7. 路径防护覆盖原始诊断 evidence、summary、location、模型输出及异常；前端不得依赖“格式化显示成文件名”掩盖 DTO 已泄露绝对路径。

### 6.3 A/B 事件、失败与恢复（AD-10/13）

| 项目 | 接口 A：Agent | 接口 B：Gateway |
|---|---|---|
| 流作用域 | session 内教学事件 | 工程事件流 |
| 等待方式 | 当前即时返回，客户端有界轮询 | 支持 wait_ms 长轮询，客户端超时须留余量 |
| 保留 | 当前每 session 1000 事件、64 run、32 会话 LRU | 当前事件窗口 10000 条/24 小时 |
| 恢复入口 | GET session、已知 run；没有 Agent `/state` | GET project `/state` 后重新订阅 |
| 重启语义 | 无持久化，不能恢复完整教学状态 | 依实际 Job/授权/快照恢复能力查询，不等于自动续跑 |

- 各流单独维护 cursor，按 sequence 去重；**分页未读完时 cursor 取最后实际消费事件，不能直接跳到 high_watermark**。现有 A 每次读取内部默认最多 100 条，指南的 watermark 续订表述需要纠正。
- A 目前没有冻结 `limit` 参数，不把 B 的 limit/wait_ms 直接传过去。需要显式分页字段时，双方新增可选 `has_more/next_after` 并补契约；不擅改现有路由。
- 410 先恢复状态再订阅；A 无法找回的历史明确显示丢失，不编造完整轨迹。
- GET 可有限退避重试；CreateSession/CreateRun 是非幂等 POST，超时/503 后不能透明自动重放。当前失败 run 的错误信封不提供 run_id，可利用已知会话事件核对；仍不明确时要求用户确认后重试。
- 401：丢弃旧连接、重新握手；403：展示策略拒绝，不靠反复重试；409：刷新版本/状态；413：缩小输入；429：按具体接口缩小输出窗口/处理限流；503：提示服务问题。以 A/B 各自 OpenAPI 为准，不套旧 spec 的统一状态码表。
- 真正需要可靠动作恢复时新增 action_id/幂等查询能力，不能靠 request_id 猜测是否执行成功。

### 6.4 Gateway 已知偏差的收口原则（AD-12/13）

- 能力发现必须检查真实工具配置、可执行文件及必要 POSIX shell。Yosys/Verilator/sh 缺失时即使插件注册也不能宣告执行 ready。就绪检查失败应有可诊断原因，不能自动安装或随意改 PATH。
- 64 位 tick：推荐新增十进制字符串输入支持，同时保留已承诺的整数输入兼容期；所有转换做范围检查，覆盖大于 2^53 的值。若现有 schema/主版本规则不允许该类型演进，采用新版本化路由，不能只改实现。
- 空源码区间的 `end_line=0` 与 schema `>=1`：明确选择返回空区间结构还是领域错误，联合修改引用客户端，不能简单把 0 伪装成 1。
- `PATH_OUTSIDE_PROJECT/SOURCE_UNAVAILABLE/PLUGIN_UNAVAILABLE` 等未登记错误：建立代码→契约映射和兼容方案；安全含义必须保留，不能统一改成成功或静默忽略。
- grant/receipt 请求验证 JSON 对象和字段类型；不能让非对象 JSON 落到通用 500 后伪装成客户端 INVALID_ARGUMENT。
- 按当前工程检查 Job/artifact 归属；若要实现项目级安全隔离，应增加项目绑定或细粒度 token/路由约束，不能仅依赖 ID 名称和 UI 当前 tab。
- 不重复开发已有的快照、grant 配额、幂等表、报告归一化和 VCD 查询；优先增强现有实现和真实负例。

## 7. B 阶段：教学版完整闭环的补充设计

本节是**建议扩展，尚未冻结/实现**。应先双方评审 DTO、动作和兼容规则，再编码；不能把下面动作直接发给当前 A 服务。

### 7.1 教学状态与逐级提示（AD-14）

U2 以现有 sidecar 为唯一对外服务，接入/迁移教学主控，不同时维护两套对 UI 开放但类型不兼容的运行时。

- 服务端保存 session/run/issue/occurrence、当前等级、教学阶段、revision、策略版本、证据摘要和动作版本。
- `hint_next` 每次真实动作最多升一级；action_id 幂等，同报告重读不增加 occurrence。学生重复失败只可建议更直接提示，不能自动升到 L4。
- 增加等待学生、等待审批、取消、复测反馈等状态；E0–E7 是教学工作流状态，不能直接塞进当前 run 的 `succeeded/degraded/failed` 枚举。
- 分开 Agent run、EDA job、教学 action 和网络请求 ID。一次 run 可关联多个 Job，但 Job 的终态不等于教学流程结束。
- 限制 L1–L3 的候选输出，规则可复现不等于结论绝对正确；模板、模型、课程检索都要遵守同一等级策略。
- 无 Key 时保留有证据的规则引导；不以“降级”掩盖无证据、过期或不支持的问题。

### 7.2 L4 的可信两步流程（AD-03）

建议新增独立教学动作接口（路径待评审，例如 session actions），而不是继续赋予 `more` 授权语义。

1. 用户第一次请求参考解，Agent 只返回说明和一次性 challenge，不读取或发送参考答案。
2. SigFlow 原生 UI 展示策略说明；用户第二次独立点击确认。自动双发请求、模型回复“已确认”、界面初始化回调都不算操作。
3. 可信 C++ 控制器用 Gateway UI 身份签发 receipt，绑定 instance/generation、project、session、issue、revision、policy、challenge、action、过期时间；learner/profile 纳入未来记录隔离。
4. Agent 校验这些绑定，再通过 Gateway 原子核销；失败、过期、跨上下文、旧策略、版本不一致均拒绝。
5. 核销成功后才加载 L4 资料并生成参考卡；action 重放返回同一结果，不再次提升等级、不重复核销。
6. 重启/保存/换工程使旧 challenge 失效；若在核销后崩溃，要能识别同 action 的已核销记录并安全恢复，不能要求用户重新绕过确认。

特别注意：当前 ReceiptStore 核销参数主要是 project/run/action/state_version，**不等于已经校验 session/issue/revision/policy/challenge**；查询响应也需补齐必要绑定字段。推荐在 Gateway 侧原子比较完整绑定，不能只由 Python“查询后认为匹配”。新必填参数/状态语义须走新动作或版本化契约，保留明确迁移说明。

`receipt.state_version` 是凭据自己的版本，初始为 0；不是 session 的 state_version。不得混用两类版本。

### 7.3 审批后验证计划与执行（AD-09/12/14）

保留原 spec 分工：Agent 选择/编排受限能力，SigFlow 决定是否授权并实际执行。**不另外建立第二套绕过 Gateway 的 GUI 执行器。**

推荐完整链路：Agent 建议计划 → C++ 规范化校验并展示 → 学生审批 → 创建已保存快照 → 可信 UI 签发有界 grant → Agent 受限客户端逐步申请 Job → Gateway/JobService 执行 → 取报告/波形 → Agent 反馈。

落地要求：

- 当前计划固定三步只是建议，不是可直接执行的 DTO。应根据问题、目标、testbench 和 ready 能力生成最小步骤；不默认每次都综合、编译、运行。
- 校验 step_id 唯一、依赖存在、无环、能力白名单、参数 schema、总配额及 stop_conditions。计划最多允许执行的 Job 数与 grant 精确一致；A 阶段的建议上限不构成执行授权。
- 当前 stop_conditions 是自然语言字符串，只可展示，不可直接作为可执行规则。执行器使用固定的服务端停止规则；需要可配置条件时另定义受限结构化枚举，禁止 eval、脚本和模型自定义表达式。
- `eda.sim.run` 必须引用同计划成功的 `eda.sim.build`。修当前 s3 未填 `build_step_id` 的缺口，再将它解析成实际 `build_job_id`；只能引用同工程/快照的可信构建结果。
- 明确 top/testbench/duration/target/options 来源。未知参数、路径、可执行文件、任意 opts 不得进入 Job；缺参数就向用户询问，不猜工具命令。
- 计划审批绑定规范化 plan_hash、revision、snapshot、步骤能力和参数。审批后任何修改都重新审批；模型不能自行生成/更换 grant、HTTP 头或幂等键。
- 计划 hash 应使用共同定义的规范化序列化算法，不依赖 Python/C++ 默认 JSON 顺序；给双方一致的 golden fixture。
- 同一步固定 Idempotency-Key，网络丢响应先查 Job/幂等状态。现有 Gateway 请求 hash 不含 grant_id、expected_revision、plan_hash、step_id，不能假定“同键”已经绑定完整教学动作；审批语义变化时不能复用旧执行 action/键。
- 遵守依赖成功、配额和停止条件；Failed/TimedOut/Cancelled、revision 改变、授权过期/撤销、证据不完整均停后续步骤，不无限自动修复或重跑。
- UI 取消先停止调度新步骤，再取消当前 Job/撤销未用授权；取消请求已接收不代表子进程已退出。
- 新增教学执行动作/查询接口，并扩展 Python Gateway typed client。当前客户端只有 fetch_job_report，不具备提交/轮询/取消全链。
- L4 receipt 与 EDA grant 分开管理：看参考答案不等于批准运行，批准运行不等于允许 L4。

执行 Gate 未过前，学生仍可用原有手动综合/仿真；计划卡标注“建议，未执行”，不能把旧手动 Job 自动认作刚获批计划结果。

## 9. 接口演进与兼容规则

1. A 阶段遵循当前实际 A：四种 kind、同步 201、即时事件、内存会话。不擅自改成旧 spec 的 202/异步 run，也不发送尚未实现的动作。
2. 修正实现不符合既有安全承诺的行为，例如 L4 失败关闭、路径/凭据保护，明确发布说明和回归；不能以兼容为由保留旁路。
3. 同主版本只做约定允许的可选新增。新增 required、改类型/枚举/状态码/动作语义时，采用新路由/主版本或明确协商后的能力扩展，不悄悄覆盖 v1。
4. 动作、持久化恢复、严格 L4、可执行计划均要有显式能力发现。老客户端忽略未知可选字段，新客户端对不支持服务隐藏入口并给原因。
5. 候选扩展字段包括 action_id、expected_state_version、challenge/receipt 引用、执行状态与恢复摘要；它们目前不是 CreateRunRequest 的既定字段，先定义请求/响应及错误场景。
6. 若改为异步运行，必须同时新增可查询状态、取消、事件和失败恢复，不能只把 201 换成 202。
7. 契约测试要覆盖**真实响应**和**非法输入被拒绝**两面。现有 SimpleSchemaRegistry 支持部分约束，不能因为 `$ref` 能解析就宣称完整 Draft 2020-12 校验。
8. 对新卡片种类/状态不明的情况只显示 unsupported；不得按“看着像计划”自动执行。

### 本轮顺带修掉的实现问题

- `KillCurrentProcess()` 统一收口"结束当前代进程"：进程已自行退出时不再调用 `Kill`（消除 `Failed to kill process (error 5)` 噪声）。
- `GatewayServer` 在包含 httplib 前把 `CPPHTTPLIB_LISTEN_BACKLOG` 从默认 5 提到 128（Linux 上 20 并发连接更稳）。
- `edu_real_tool_smoke` 工具发现按平台区分：POSIX 只用系统 PATH 上的原生工具，拒绝仓库随附 runtime 里的 Windows `.exe`（WSL 互操作会把 PE 二进制跑起来，制造假通过/假失败）。

### 已知未解决：Linux 并发传输间歇失败

`edu_gateway_fault_smoke` 的 20 线程同幂等键用例在 Linux 上约 **1/3 批次**出现 **1 个 `-1`**（httplib `Error::Read`，即对端提前关闭连接，非 5xx、非超时——失败运行整体仅约 2 s）。已在测试里加了状态分布与传输错误码打印以便定位。已排除：监听 backlog（提到 128 后仍复现）、线程池队列上限（httplib 默认 `mqr=0` 即无上限）、处理器缺 `send()`（该路径的早退都先 `send`）。该现象在本轮改动前就存在（未触碰提交路径），暂记为**待定位的间歇性问题**，不通过放宽断言来"修掉"。
