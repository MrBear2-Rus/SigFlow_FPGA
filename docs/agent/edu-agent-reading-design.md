# Edu Agent 内容浏览增量设计

基线为 `f7fe3cb`。设计日期为 2026-11-15。实施与验收见 [任务清单](edu-agent-reading-task.md)。

本轮目标是在 Windows 原生工作台上，通过鼠标滚轮、拖动条或键盘完整阅读当前已加载的教学内容。覆盖中央工作台、停靠和浮窗中的对话、学习路径及教学辅助区。延续[原 GUI 规格](SigFlow-Edu-Agent-GUI-Spec.md)的分区、主题和工作台形态。滚动、重排和阅读位置由 C++ GUI 负责，教学卡片、权限、记录和工程证据仍以正式宿主为准。

## 现状与设计选择

1. `AgentWorkspace::RevealSection` 会在侧栏跳转时主动重算教学辅助区域。用户直接点击折叠标题时，`AgentAccordion` 发送 `EVT_AGENT_ACCORDION`，但当前工作台没有监听它。分区高度变了，外层滚动范围仍可能滞后。
2. `ScrollPageTo` 收到卡片相对于 `m_sheet` 的位置，再作为整页虚拟位置使用。目前 `m_sheet` 放在虚拟原点，所以直属卡片的位置可以与整页虚拟位置一致。真正需要验证的是滚动后目标是否完整可见，以及布局更新后直接使用点坐标是否仍能准确定位。增量设计用目标矩形和当前视口判断定位范围。
3. `AgentConversation` 使用原生只读多行控件实现选择和复制，文本控件和对话滚动窗口之间还有消息行窗口。鼠标停在正文时的事件归属，以及长文本最后一行是否被文本控件自身裁掉，必须用 Windows 原生窗口分别验证。
4. `ArrangeGuide` 先为固定尾注预留位置，再用剩余高度放步骤列表。窄幅、高 DPI 或短浮窗下，列表高度可以为零。外层滚动范围即使正确，也无法读到零高子窗口里的步骤。

保留分区内滚动，集中修正测量、事件交接和定位。这样宽屏仍可独立查看对话和证据，窄屏仍按对话、学习路径、教学辅助的顺序浏览。按分区临时增加高度只能覆盖个别样例。把全工作台改成单一滚动页面会改变宽屏对照阅读和输入区位置，改动范围较大。

## 1. 内容高度与滚动范围

`AgentWorkspace` 持有整页、学习路径和教学辅助的布局。`AgentConversation` 持有消息行的高度和阅读锚点。各滚动容器以实际客户区尺寸为视口，以所有可见内容最下沿加留白为虚拟高度。发生正文更新、展开收起、视口变化或 DPI 变化时，以同一条布局路径测量。折叠标题的事件在工作台接收，布局重排合并到一次界面更新。

竖滚动条改变可用宽度后，用新宽度重新测量换行和高度。首轮排版后如客户宽度改变，追加一次测量。如控件仍在发尺寸事件，在下一次界面更新校正，避免在同一个尺寸回调里递归重排。整页断点继续使用工作区逻辑宽度，分区和正文换行使用各自实际客户宽度。

跳转顺序为先让目标所在卡片可见，再展开目标分区、更新虚拟高度并定位到标题。卡片和标题由同一个可见性判断使用各自滚动容器的虚拟坐标。已经可见时保持原位置。重复点击同一侧栏项应停在同一目标附近。内容收起或缩短时把当前位置夹到新范围内。

## 2. 鼠标、键盘和阅读位置

鼠标位于对话、学习路径或教学辅助时，竖向滚轮优先滚动指针下最近的可滚动区域，该区域到达边界后交给可继续滚动的上层。对于吞掉竖向事件的原生正文控件，在工作台范围内将事件转给其所属滚动区。一次输入只产生一次滚动，保留高精度设备的累计滚轮增量。代码和宽表格继续提供横向滚动，文本选择、复制、输入框键盘操作及浮窗标题拖动各自使用原有交互。

使用原生竖向滑块。有溢出时显示并可拖至顶部或底部，在无需滚动时隐藏。正文区获得焦点时可通过 Page Up、Page Down 和 Home、End 浏览，输入框的编辑按键优先。分别测试指针和焦点处在不同区域的情况。

对话沿用消息 ID 与行内偏移。新回复到达前位于底部的视图继续跟随，正在读旧消息时恢复原锚点。教学辅助优先保留分区和分区内偏移，分区消失时夹到有效位置。切换主界面形态或调整窗口时保留同一工程、修订和运行的阅读位置。切换工程、修订或运行时，按当前工作台的身份边界重置对应锚点。

## 3. 窄窗口与长文本

学习路径空间充足时保留固定尾注。固定尾注会把路径列表压到不足以显示一个步骤时，将尾注放进同一滚动内容区末尾。长中文说明、诊断文本、链接和标识按实际客户宽度换行，测量包含字体、内边距以及代码或表格的横向滚动条占高。输入和教学操作按钮在短窗口仍能通过整页滚动达到。

正文区滚动修复后，再为课程引用、学习记录和证据链提供按项「查看全文」或「复制」。入口只使用已授权且已投影的数据，切换运行或修订后关闭旧详情。对服务返回的限量结果明确显示「仅显示最近记录」或相应上限提示，避免用户把服务端未返回的行当成显示裁切。

## 4. 较早教学时间线

此项独立于滚动修复。现有 `GET /api/v1/u2/runs/{run_id}/timeline` 支持最近一页及 `after` 向后续读。直接用现有 `after` 猜测上一页起点会遇到保留窗口过期或边界不明确，无法稳定向旧记录翻页。

待宿主接口协作确认后，为同一路由增加可选的 `before`，与 `after` 互斥。首次加载沿用最近 12 条。向前翻页时传当前最早事件的序号，按序号筛选严格小于该值且仍保留的事件，取最近一页并以升序返回。响应保留当前身份字段和水位，新页标志按本次结果之前是否还有已保留事件计算。页首没有更早数据时关闭加载入口。游标超过当前水位时沿用无效游标处理，触及淘汰边界时明确告知可读历史范围。

客户端在原有「证据链」内显示「加载较早记录」。请求在后台读取，合并前复核工程、修订、运行、会话和状态版本。按事件序号去重，插入旧页后恢复原来的阅读锚点。现有学习记录接口保持最近记录视图，其更早历史由独立的 UA-10 契约决定。

## 发布与验证边界

第一批交付教学辅助区、跳转和滚动输入，第二批交付紧凑布局和可读性。每批都用真实 Windows 窗口验证。长内容和异步更新可用确定性数据构造，另用全加器工程、正式宿主和规则模式验证完整教学路径。较早时间线分页独立验收，涉及服务协议时同步路由契约、兼容测试和变更记录。
