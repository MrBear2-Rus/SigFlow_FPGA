# SigFlow 双版本开发规划（汇报版）

> 版本 v0.9（评审稿） · 2026-09-01
> 详细技术方案见 `docs/SigFlow-Dual-Edition-Plan-0831.md`（本文件是其面向评审的浓缩版）
> 读者：导师、组内学长。重点请看 §2 定位、§5 路线图、§6 需要拍板的问题。

---

## 1. 一句话概括

SigFlow 在现有"开源 EDA 工具链 + TraceBridge 硬件调试闭环"的底座上，分化为**教育版**与**工程版**两个产品方向；AI 不再定位为"自动写代码的引擎"，而是贯穿全流程的**理解、分析与辅助决策助手**——工具的执行交给既有的 Job 化框架，AI 只负责生成参数、解读结果、辅助用户决策。

## 2. 两个版本分别是什么

### 2.1 教育版（SigFlow Edu）—— 数字电路教学

- **入口不变**：仍以现有的拖拽式原理图设计为主入口，保留图码同步。
- **核心体验**：原理图、RTL 代码、仿真波形、综合结果四个视图联动——学生画一个门电路，能立刻看到对应代码、波形和上板后的资源占用。
- **Agent 角色：教学助手，不给答案**。学生在设计过程中的典型错误（组合环、锁存器推断、位宽不匹配等）会被自动识别，Agent 通过 L1→L4 分级提示（方向性提问 → 逐步缩小范围 → 参考解法需二次解锁）引导学生自己找到问题。
- **远期预留**：教材适配（一生一芯、PA 课等），本期只预留课程包接口，不做实现。

### 2.2 工程版（SigFlow Pro）—— FPGA/RTL 工程开发

- **设计视图升级**：不再以逻辑门为主要单元，提供层次化设计视图——顶层看系统架构，逐级展开模块直到 RTL 实现；模块之间以总线连接，点击总线可查看位宽、协议、驱动端、负载端。
- **三方联动**：代码、设计图、波形之间任意跳转（点波形信号 → 定位到代码行 → 在设计图中高亮该模块）。
- **Agent 角色：设计理解与调试助手**。用户在设计图里点一个模块、信号或总线，或在波形上框选一段，直接向 Agent 提问；Agent 结合设计结构、源码、连接关系和波形数据分析作答。
- **AI 如何"看懂"大规模设计**：引入 Context Engine——AI 不直接读整个工程源码，而是按用户当前关注点（点了谁、框了哪段）自动取局部结构化上下文（模块层次、连接关系、源码位置、波形切片）再交给大模型。既控制上下文规模，又与可视化设计天然联动。

## 3. Agent 工作范式（本规划最重要的修订）

对硬件开发流程做"大致完善但容许选择"的编排：

```
RTL 编写 → 仿真 → 综合 → 布局布线 → 烧录调试(可选) → 结果比对 → 达标？
    ▲                                                      │
    └────────────── 未达标：修改后回环 ←────────────────────┘
```

核心原则——**AI 只关注三件事**：

1. **输入**：结合用户意图生成各工具 Job 所需的参数；
2. **输出**：Job 运行后解读产物与结构化报告（如"综合有 3 个警告，其中 1 个疑似锁存器推断"）；
3. **用户干预**：每个阶段结束给出决策卡（继续 / 回退 / 改参数 / 中止），由**用户**决定下一步。

以 Yosys 为例：仿真通过、用户查看波形后决定进入综合 → AI 按用户提示生成综合参数 → Job 自动执行、产出网表与报告 → AI 总结异常点呈现给用户 → 用户决定继续布线还是回头改 RTL。

这条原则同时确定了边界：**AI 不直接执行工具、不直接改用户代码、不代替用户做阶段决策**，所有决策留有记录、可回溯。

## 4. 现有系统怎么用（不推倒重来）

| 现有资产 | 在规划中的角色 |
|---|---|
| Yosys / nextpnr / 打包 / 下载 Job 化执行框架 | 直接复用，补齐仿真/烧录的 Job 化，统一结构化报告格式 |
| TraceBridge 硬件调试闭环 | 工程版作为 Agent 问答的硬件信号源；教育版做简化教学版 |
| 拖拽原理图、图码同步（SFTree 等） | 教育版主入口，强化四视图联动 |
| 波形系统（WavePanel、双轨比较、根因分析） | 两版共享，新增"框选提问"交互 |
| 插件/特性开关机制 | 作为双版本分化机制（同一代码库、双构建目标） |

**需要新建的只有四块**：设计中问表示（Design IR，支撑层次视图与联动）、局部上下文引擎（Context Engine）、流程编排与决策门（FlowGraph/StageGate）、教育版错误模式库与分级提示引擎。均以新增模块实现。

**界面原则：现有页面基本不动**。主窗口、编辑器、波形面板、TraceBridge 窗口等保持现状；新能力一律以"新增面板/浮层"形式叠加（层次视图、Agent 对话面板、决策卡、提示卡均为新增组件），不重构现有页面。工程版默认不出现门级原理图相关界面，教育版不出现工程版专属面板——靠特性开关控制可见性，而不是改页面。

## 5. 实施路线图（按迭代推进）

| 阶段 | 内容 | 产出标志 |
|---|---|---|
| **P0 底座统一** | 仿真/烧录 Job 化、统一报告格式、AI 骨架（先接 Mock） | 全流程以 Job 形式跑通，报告可被程序化读取 |
| **P1 工程版数据底座** | Design IR + 层次化设计视图 + 总线面板 + 三方联动 | 打开示例工程可从顶层逐级展开到 RTL，点总线看属性 |
| **P2 AI 接入** | Context Engine + 工程 Agent 问答（点谁问谁、框选提问） | 示例工程上完成一次真实的设计问答与报告解读 |
| **P3 流程编排** | FlowGraph + 决策门，Agent 贯穿全流程 | RTL→仿真→综合→布线→调试→回环全流程带决策卡走通 |
| **P4 教育版核心** | 四视图联动强化 + 错误模式库 + 分级提示 | 教学示例上完整演示"学生犯错 → 分级引导 → 自行修复" |
| **P5 远期** | 教材/课程包适配、多板卡支持等 | 按需立项 |

P1/P2（工程版）与 P4（教育版）可在 P0 之后并行推进。每个阶段都尽量在 1–2 个迭代内拿到可演示的产出。

## 6. 请导师/学长重点评审的问题

1. **Agent 定位**：从"自动闭环修复"改为"用户决策 + AI 辅助"（copilot 而非 autopilot），是否认可？这决定了后续所有 Agent 设计走向。
2. **双产品 vs 单产品双模式**：教育/工程分化已深入到设计单元与数据模型层面，我们倾向单代码库、双构建目标，是否同意？
3. **优先级**：先做工程版（P1–P3）还是教育版（P4）？当前排布默认工程版优先，若教学场景（课程合作）有明确时间点，可对调。
4. **范围控制**：P5 教材适配本期只留接口不做实现，是否符合预期？

## 7. 风险与对策（简表）

| 风险 | 对策 |
|---|---|
| LLM 分析硬件设计的效果不确定 | P2 先用 Mock + 规则模板打通链路，效果验证后再接真实模型 |
| 层次化视图 + Design IR 工作量大 | 严格分阶段验收，P1 先支持两层展开即可演示 |
| AI 输出不可靠 | AI 只建议不执行；决策留痕；关键操作（烧录）强制用户确认 |
| 双版本摊薄人力 | 底座全部共享，分化部分通过特性开关隔离，单人可先专注一版 |
