# SigFlow 项目介绍

### Thank you for choosing SigFlow Team

## 1. 项目是什么

**SigFlow 是一套面向数字电路与 FPGA 开发的集成式 EDA 平台。**

它把原本分散在多个软件和命令行工具中的工作整合到一个图形化开发环境中，让用户能够完成：

```text
画电路 / 写 Verilog
        ↓
      仿真验证
        ↓
       逻辑综合
        ↓
      布局与布线
        ↓
      生成 FPGA 位流
        ↓
       下载到开发板
        ↓
  采集真实硬件波形并定位问题
```

简单来说，SigFlow 想做的是一个**更直观、更开放、可扩展、适合教学，同时能够连接真实 FPGA 硬件的RTL开发平台**。

## 2. 项目主要解决什么问题

传统 硬件设计与RTL和FPGA 开发通常需要在代码编辑器、仿真器、综合工具、布局布线工具、下载工具和波形软件之间反复切换。各阶段产生的日志、报告和文件也比较分散，出现问题后很难快速判断问题来自代码、工具配置还是硬件。

SigFlow 将这些环节连接成一个统一流程：

- 用图形或 Verilog 描述数字电路；
- 用仿真提前检查逻辑行为；
- 用开源工具链完成综合、布局布线、打包和下载；
- 从真实 FPGA 中采集内部信号；
- 对比仿真与实测波形，帮助定位第一个异常位置；
- 保存每次任务的输入、日志、报告和产物，使结果可以追溯和复现。

## 3. 当前具备的核心能力

### 3.1 设计与编辑

- 图形化数字电路设计，包括元件、引脚、导线和画布操作；
- Verilog 代码编辑与结构解析；
- 使用 SFTree 表示工程、模块、端口、信号和实例关系；
- 支持代码与结构图之间的关联，为后续定位和 Agent 理解工程提供基础。

### 3.2 仿真与波形

- 使用 Verilator 编译并运行仿真；
- 加载和分析 VCD 波形；
- 支持波形缩放、时间窗口、信号搜索、模式搜索和比较；
- 使用懒加载、缓存和内存预算机制处理较大的波形文件。

### 3.3 FPGA 开源工具链

| 阶段 | 工具 | 作用 |
| --- | --- | --- |
| 仿真 | Verilator | 在电脑上执行 RTL 仿真 |
| 综合 | Yosys | 将 Verilog 转换为逻辑网表 |
| 布局布线 | nextpnr | 将逻辑映射到具体 FPGA 资源 |
| 位流打包 | Apicula / `gowin_pack` | 生成 Gowin FPGA 的 `.fs` 位流 |
| 下载 | openFPGALoader | 将位流写入开发板 |

当前主要验证目标是 **Tang Nano 9K**，使用 Gowin GW1N 系列 FPGA。

### 3.4 Job 任务系统

外部工具不是简单地执行一条命令，而是被封装为可管理的 Job。每个 Job 通常包含：

- 状态机和任务 ID；
- 独立运行目录；
- 输入、脚本、日志和输出产物；
- 超时、取消和失败处理；
- 结构化报告与 manifest；
- 工具版本及 SHA-256 指纹。

这样可以回答三个重要问题：**运行了什么、为什么失败、这个结果来自哪一次构建。**

### 3.5 插件化架构

项目正在将 EDA 能力拆分为独立插件。目前仓库中包括：

- Verilator 仿真插件；
- Yosys 综合插件；
- nextpnr 布局布线插件；
- Gowin 打包插件；
- openFPGALoader 下载插件；
- Tang Nano 9K 目标板插件；
- Gowin CST 约束插件；
- VCD 波形插件；
- 基础元件库插件。

核心和界面通过统一能力接口使用插件，尽量不直接依赖某个具体工具。这使后续增加新器件、新开发板或新工具时，不需要大规模修改主程序。

## 4. TraceBridge：自研软硬件调试系统

TraceBridge 是 SigFlow 的重要特色。它类似 FPGA 厂商提供的片上逻辑分析仪，但与 SigFlow 的构建、波形和工程系统直接连接。

它由三部分组成：

1. **FPGA 侧**：轻量采集核、触发逻辑、UART 和调试协议；
2. **构建侧**：根据调试契约生成 Overlay，在不直接修改用户原始 RTL 的情况下接入采集逻辑；
3. **主机侧**：配置采集、读取样本、生成 VCD，并与仿真波形进行比较。

目前已经实现的主要能力包括：

- FPGA 内部信号采样、触发和环形缓存；
- UART 回传与完整性校验；
- 自动生成调试位流；
- 真实硬件波形采集；
- 仿真波形与硬件波形自动对齐；
- 首个差异位置定位和根因候选分析；
- 使用真实采集输入重新运行仿真；
- 通过契约、构建指纹和哈希保证源码、位流与波形同源。

Tang Nano 9K 已完成从 RTL、综合、布局布线、打包、下载到硬件采集的完整链路验证。

## 5. 我们现在重点在做什么

当前主线是在已有 FPGA 平台上建设 **SigFlow 教育版和原生教学 Agent**。

这个 Agent 不是简单的聊天窗口，而是能够读取真实工程上下文的数字电路助教。它需要理解：

- 当前工程结构和 Verilog 源码；
- 用户选中的模块、信号或波形区间；
- 本期教学范围内的仿真、综合报告，以及可追溯的波形；
- 工具产生的诊断信息；
- 学生过去遇到的问题和学习记录；
- 当前课程允许使用的资料和教学策略。

当学生遇到锁存器、位宽不匹配、复位异常等问题时，Agent 采用 L1～L4 分级提示：先给方向，再逐步缩小范围，必要时经二次确认展示参考解法。它不会自动修改学生工程，也不会绕过 SigFlow 直接运行 EDA 工具。

整体分工如下：

```text
SigFlow 原生教学界面
        ↓
Python 自研教学 Agent（参考 UCAgent 架构）
        ↓
SigFlow EDA Gateway
        ↓
工程快照 / JobService / 插件 / 报告 / 波形
```

- **C++ SigFlow**：负责工程、界面、插件、EDA 任务、报告、波形和执行授权；
- **EDA Gateway**：通过本地 HTTP 提供受限、可追溯的工程能力；
- **Python 自研 Agent**：参考 UCAgent 的分阶段工作流、受限工具和检查思路，自行实现教学推理、分级提示、课程检索和学习记录；不依赖 UCAgent 运行时；
- **用户**：决定是否执行仿真或综合计划；烧录等硬件操作仍走原有手动流程，不开放给教学 Agent。

当前教育 Agent 的接口契约、工程快照、报告归一化、权限、幂等、事件和 Gateway 服务正在持续开发。自研教学服务需在原生 Windows/Linux 上运行并与 SigFlow 完整联调；原生教学面板也仍是当前重点，不能把设计稿或 Mock 当作已经上线的产品功能。Docker/远端部署等方案留待工程版按用户需求评估。

## 6. 产品的未来方向

项目采用同一代码库，并预留两个Agent产品发展方向：

- **SigFlow Edu**：面向数字电路和 FPGA 入门教学，强调图、代码、波形和报告联动，以及“引导而不是代做”的教学 Agent；
- **SigFlow Pro**：面向 FPGA/RTL 工程开发，未来强化层次化设计浏览、复杂波形分析和工程调试助手。

当前实施重点是教育版。工程版也计划自行实现 Agent，仅参考 UCAgent 架构；其目标、部署方式和 Docker 需求后续单独确定，不属于本期交付范围。
