# SigFlow 教育版全功能演示视频规划

> 文档版本：v1.0  
> 规划日期：2026-09-30  
> 适用范围：SigFlow 教育版、SigFlow 基础 IDE、插件化 EDA 工具链、TraceBridge、教育版 Agent 协作  
> 不包含：工程版 Agent 的自动改代码、全流程自主修复、设计空间探索等后续能力

## 1. 视频目标

本视频要回答四个问题：

1. SigFlow 是什么，为什么它不只是一个 Verilog 编辑器？
2. 学生如何从 RTL/图形设计走到仿真、综合、布局布线、打包和上板？
3. TraceBridge 如何把真实 FPGA 内部行为带回 SigFlow，并与仿真波形对照？
4. 教育版 Agent 如何基于真实工程、报告和波形逐级引导，同时受到版本、权限和工具白名单约束？

视频的核心叙事不是逐个打开菜单，而是让观众看到一个完整闭环：

```mermaid
flowchart LR
    A[打开教学工程] --> B[RTL 与结构图理解]
    B --> C[仿真与波形观察]
    C --> D[综合发现问题]
    D --> E[Agent L1-L3 引导]
    E --> F[学生手动修复]
    F --> G[授权复测]
    G --> H[PnR / Pack / Program]
    H --> I[TraceBridge 硬件采集]
    I --> J[仿真/硬件双轨比对]
    J --> K[证据定位与学习记录]
```

建议交付三个版本：

| 版本 | 时长 | 用途 | 内容 |
| --- | ---: | --- | --- |
| 全功能母版 | 45–52 分钟 | 验收、评审、团队展示 | 覆盖本文全部可演示功能和技术证据 |
| 产品精华版 | 8–10 分钟 | 比赛答辩、路演、对外介绍 | 保留完整闭环，压缩工具等待和技术附录 |
| 竖屏/短视频版 | 60–90 秒 | 宣传、开场暖场 | 图码联动、Agent 引导、上板采集、首差异四个高光 |

以下时间轴以约 50 分钟的全功能母版为基准。

## 2. 演示范围和真实性分级

录制时必须区分“当前可以现场运行”“可以展示底层证据”“仍依赖双方联调”。不得用静态 Mock 冒充完整产品能力。

### 2.1 A 类：当前适合现场演示

- 工程创建、打开、保存和工程树管理。
- Verilog/SystemVerilog 编辑、语法高亮、行号、代码折叠。
- Tree-sitter 驱动的结构解析和 SFTree 展示。
- 结构画布、元件库、放置、选择、拖动、框选、缩放、平移、连线、文本和属性查看。
- FPGA 引脚绑定与 CST 约束编辑/校验。
- Verilator 编译、仿真、取消、缓存清理和 VCD 自动加载。
- 波形信号树、搜索、缩放、Fit、游标/播放头、A-B 测量、标记、模式搜索、别名、备注、会话保存/恢复、UART lane、主题切换。
- Yosys 综合 Job、运行时检查、进度、取消、重试、日志、结构化报告、错误源码跳转。
- nextpnr 布局布线 Job、CST 注入/校验、资源及时序报告、取消和重试。
- Gowin Pack 生成 `.fs`、manifest 和哈希。
- openFPGALoader 人工确认后的板卡下载。
- TraceBridge 单时钟 Debug Contract、Overlay、构建、下载、采集、会话、导入导出、HW VCD、重放 VCD、仿真/硬件波形比对和首差异定位。
- 插件发现、能力注册、默认后端选择、内置工具链运行时。
- Windows CMake 构建；Linux/麒麟画面仅在对应机器已完成同版本验收后录制。

### 2.2 B 类：适合放入“技术证据”章节

- 本地 EDA Gateway 的 health、capabilities、context、snapshot、source、job、report、artifact、wave、event 接口。
- revision/dirty 状态和不可变快照。
- Job grant、`max_jobs` 配额、撤销、幂等键和重启恢复。
- UI receipt 的签发、查询、一次性消费和同 action 重放。
- 报告归一化、artifact 有界读取、波形精确查询及分页。
- 受控目录、哈希、manifest 和 Job 产物追溯。
- CTest/契约测试结果及跨平台构建矩阵。

这部分应采用屏幕录制、简短动画或终端/API 面板展示，不需要让普通观众阅读大段 JSON。画面只突出关键字段。

### 2.3 C 类：只有完成 UCAgent 与原生 UI 联调后才能作为真实功能录制

- 原生教学 Agent 面板和 sidecar 生命周期状态。
- 锁存器问题的 L1→L2→L3 分级提示。
- L4“申请参考解法→确认卡→再次确认→展示参考解法”的两步门控。
- 课程 RAG 引用和受控 URL。
- 学习历史、同类错误记录、个性化提示和记录删除。
- Agent 生成有界验证计划，学生批准后使用 grant 调用真实 `sim.build/sim.run/synth`。
- 无模型 Key、网络断开、Agent 崩溃时的规则降级和 IDE 独立可用。
- EvidenceRef 在原理图、RTL、报告、波形之间跳转。

若录制当天尚未完成这些联调，只能将本节改为“规划架构与当前后端准备情况”，不能把设计稿或 Mock 卡片描述成已经上线。

### 2.4 本期不要宣称的能力

- 工程版 Agent 和自动修改学生 RTL。
- Agent 自动执行 PnR、Pack、Flash 或硬件 Debug；教育版当前只应开放受控仿真和综合。
- 无人确认自动烧录 FPGA。
- TraceBridge 多时钟端到端产品流程；现阶段只有底层 RTL/结构基础。
- `comb_and` 组合触发，除非契约、主机和 RTL 已统一实现并完成验收。
- 对所有 FPGA 器件和开发板的通用支持；当前主演示目标为 Tang Nano 9K。
- “AI 保证设计正确”或“综合成功等于功能正确”。

## 3. 演示工程与素材准备

### 3.1 主工程

以 `examples/tracebridge_tangnano9k` 为基础制作一份只用于录制的副本，建议命名为 `sigflow_edu_demo`。主设计应同时包含：

- 27 MHz 板载时钟；
- 可见 LED 计数输出；
- UART 发送模块；
- 一个容易观察的状态机或计数器；
- 完整 testbench；
- Tang Nano 9K CST；
- 单时钟 TraceBridge Debug Contract；
- 仿真 VCD 和已验收的硬件 capture；
- 一处可控的教学问题，例如组合逻辑分支未完全赋值导致锁存器推断。

录制副本保留两个 Git 标签或压缩包：

- `demo-broken`：包含锁存器问题，用于 Agent 教学和失败报告。
- `demo-fixed`：学生手动修复后的版本，用于复测、PnR、打包、下载和调试。

不要在录制过程中临时手写大量 RTL。需要修改的地方控制在 1–3 行，并提前准备准确的光标位置。

### 3.2 预生成证据

在正式录制前生成并校验：

- 一份带锁存器诊断的 Yosys Job。
- 一份修复后的干净 Yosys Job。
- 一份成功 nextpnr Job，包含资源和时序指标。
- 一份成功 Pack manifest 和 `.fs` 哈希。
- 一份仿真 VCD。
- 一份硬件采集 `capture.raw` 和 `capture.vcd`。
- 一份存在首差异的仿真/硬件组合，用于比对演示。
- 一份完全一致的组合，用于说明“没有发现差异”的边界。
- 一份 TraceBridge 会话导出包，用作实时板卡故障时的回退素材。
- Agent 的真实 session/run 记录；若只能使用 Mock，必须在画面上标注“Mock/交互原型”。

### 3.3 设备和画面

- 主屏幕：1920×1080，100% 或 125% 缩放，录制前固定缩放比例。
- 字体：编辑器不小于 18 px，终端不小于 16 px。
- 板卡机位：Tang Nano 9K、USB 连接和 LED 独立近景。
- 可选第二机位：主持人操作或板卡全景。
- 鼠标高亮：开启点击圆环，但不要使用过大的拖尾效果。
- 关闭桌面通知、聊天软件、自动更新和无关窗口。
- 工程路径不要出现个人姓名、Token 或敏感目录。
- 固定 COM 端口，录制前排除串口被其他程序占用。

## 4. 全功能母版分镜

### 4.1 00:00–00:45｜高光开场

画面快速切换：

1. RTL 代码与结构图同屏。
2. Yosys Job 从 Running 变为 Succeeded。
3. 仿真波形与硬件波形双轨同屏。
4. 比对结果定位第一个差异。
5. Agent 给出 L1 提示，画面明确“不给答案”。
6. Tang Nano 9K LED 工作。

旁白建议：

> SigFlow 把 RTL、结构图、仿真、开源 FPGA 工具链、真实硬件采集和教学 Agent 放进同一个可追溯工作流。学生看到的不只是一个报错，而是从设计证据到理解、修复和复测的完整过程。

不要在开场展示长日志或菜单。

### 4.2 00:45–02:15｜产品定位与架构

画面：一张简洁架构图，随后切回 SigFlow 主界面。

讲清楚：

- C++ SigFlow 负责工程、RTL、波形、报告和 EDA 工具执行。
- Python UCAgent 负责教学推理、计划和反馈。
- 两侧通过本地 HTTP 契约通信。
- EDA 命令仍由 SigFlow 的 JobService 和插件执行。
- 学习模式不自动改学生代码，烧录和高风险动作保留人工确认。

屏幕角落持续出现一句定位：

> 确定性工具识别问题，Agent 负责把证据转化为学习引导。

### 4.3 02:15–05:00｜启动、工程和跨平台

操作顺序：

1. 启动 SigFlow，展示无工程状态。
2. 新建或打开 `sigflow_edu_demo`。
3. 展示工程树、最近项目、保存入口和当前工程标题。
4. 展示 `.sigflow` 工作目录只保存运行证据，不修改用户 RTL。
5. 在终端中短暂展示插件加载报告。
6. 打开“Toolchain Backends”或对应后端菜单，展示同一能力可由插件提供。
7. 若跨平台录屏已验收，用 5–8 秒分屏展示 Windows 与 Linux/麒麟打开同一工程。

旁白重点：

- 工具和路径从可执行目录/工程配置解析，不依赖录制者当前工作目录。
- 插件化后，综合、PnR、打包、下载、仿真、目标板、约束和波形能力彼此解耦。
- 跨平台画面必须使用同一版本和同一演示工程。

### 4.4 05:00–09:00｜RTL 编辑、SFTree 与结构理解

操作顺序：

1. 打开顶层 RTL，展示语法高亮、行号和模块折叠。
2. 展开 Project Manager，说明文件组织。
3. 切换到 SigFlow Tree，依次展开 Module、Port、Wire/Reg、实例、Assign/Always 等节点。
4. 点击一个实例或信号，展示属性面板。
5. 在 RTL 中轻微修改一个标识符或参数并保存，展示结构刷新。
6. 点击层次中的 UART 或计数器实例，回到对应源文件。

旁白重点：

- SFTree 是从 RTL 语义解析得到的结构模型，不是文件名列表。
- 后续报告、波形和 Agent 引用都需要绑定到具体工程 revision 和真实 source ref。
- 编辑缓冲未保存时应显示 dirty；需要运行 EDA 时必须先形成确定版本。

### 4.5 09:00–13:00｜结构画布与图码协同

操作顺序：

1. 打开顶层结构画布。
2. 展示元件库中的 Wiring、逻辑门、组合模块、存储和 I/O 分类；无需逐个点遍所有元件。
3. 放置一个逻辑门或模块实例。
4. 演示 Select、拖动、框选、平移、缩放、文本和 Wiring Tool。
5. 连接两个引脚，移动元件，展示连线端点跟随。
6. 展示悬停引脚和连接点高亮。
7. 使用 Undo 恢复一次修改。
8. 点击图中实例，切换到 SFTree/属性或对应 RTL。

画面验收：

- 拖动时不出现元件、文字、引脚标签和蓝色选中框残影。
- 缩放和平移后仍能准确选择和连线。
- 不演示仍是消息框占位的 Edit/Project 菜单项。

### 4.6 13:00–15:30｜目标板和引脚约束

操作顺序：

1. 打开 `FPGA > Pin Binding`。
2. 展示 Tang Nano 9K 封装/引脚视图。
3. 将 `clk`、LED、UART 和 Debug UART 绑定到目标管脚。
4. 展示 I/O 类型、驱动强度等字段。
5. 故意制造一次重复引脚或非法约束，展示校验信息。
6. 修复后生成/保存 CST。

旁白重点：约束是 FPGA 设计的一部分，SigFlow 会在 PnR 前校验约束，避免把明显冲突交给后端工具。

### 4.7 15:30–19:30｜Verilator 仿真 Job

操作顺序：

1. 打开 testbench，说明输入激励和预期行为。
2. 执行 Compile Simulation Model。
3. 展示非阻塞进度、Job 状态和终端摘要。
4. 快速演示 Cancel：使用一个专门准备的慢任务，取消后进程树退出。
5. 再次编译成功，执行 Run Simulation。
6. 展示 VCD 产物自动打开。
7. 说明 Clean Simulation Cache；不要为了录制真的清掉主演示缓存，可在副本工程演示。

旁白重点：

- 仿真同样走 Job 和受控工具路径。
- 成功只表示本次激励下仿真完成，不代表覆盖了所有行为。

### 4.8 19:30–24:00｜内置波形分析

操作顺序：

1. 展开模块化信号树，搜索 `clk`、`rst_n`、`state` 和 `led`。
2. 勾选信号，展示位宽和值。
3. 演示 Zoom+/Zoom-/Fit、拖动时间窗和播放头。
4. 设置 A/B 区间，展示时间差或周期测量。
5. 添加 Marker，并清除 Marker/A-B。
6. 给信号设置 alias 和 comment。
7. 使用模式搜索，例如 `clk:rise,state:0010`，演示 Prev/Next。
8. 保存 Wave Session，改变显示后再恢复 Session。
9. 切换 Dark/Light 主题。
10. 如果有 `capture.raw`，加载 UART lane，双击帧跳转到对应时间。

旁白重点：VCD 采用懒加载和缓存机制，适合处理较大波形；后续 Agent 查询的是精确时段和具体信号，而不是一张截图。

### 4.9 24:00–29:30｜Yosys 综合与结构化诊断

先切换到 `demo-broken`。

操作顺序：

1. 打开 FPGA Tools 的 Yosys 页。
2. 点击 Start Synthesis。
3. 展示运行时预检、Job ID、状态迁移和进度。
4. 展示 Job 列表和独立运行目录概念。
5. 打开 Summary、Warnings、Errors、All Diagnostics 过滤。
6. 选择锁存器诊断，点击 Open Error Source 跳到对应 RTL 行。
7. 展示 Open Log 和 Open Report。
8. 快速展示 Cancel、Retry 的存在；取消可以用备用 Job，不破坏主线。
9. 在文件浏览器或画面叠层中说明 `inputs/scripts/logs/artifacts/reports/manifest.json`。

旁白重点：

- Yosys 原始日志由确定性解析器转为结构化诊断。
- Job 保存输入、脚本、工具版本、输出和状态，便于复现。
- Agent 使用规范报告，不会自己从一段日志中猜测第二套事实。

### 4.10 29:30–35:00｜教育 Agent：锁存器教学闭环

本章只有在 C 类联调完成后录制。

操作顺序：

1. 在锁存器诊断旁点击“解释此问题”。
2. 展示 L1：描述观察到的现象并提出方向性问题，不给修复代码。
3. 学生点击“更多提示”，展示 L2：缩小到组合逻辑分支完备性，并提供课程引用。
4. 再点击一次，展示 L3：定位具体信号/分支，要求学生预测未命中条件时的输出。
5. 展示课程引用来自受控元数据，可点击打开对应章节。
6. 学生回到 RTL 手动补全分支并保存。
7. Agent 提出“重新综合验证”的有限计划，明确目标、步骤和预期观察。
8. 用户批准后，SigFlow UI 签发 grant；Agent 携带 grant 提交 `eda.synth`。
9. 新 Job 使用新 revision/snapshot，旧报告明确标记为旧版本证据。
10. 展示新报告中锁存器诊断消失。
11. Agent 的结论必须说“本次综合未再报告该锁存器”，不能说“整个设计完全正确”。

L4 建议作为 60–90 秒独立插段：

1. 在 L3 后点击“申请参考解法”。
2. 只显示确认卡，不显示答案正文。
3. 点击“确认查看”，由 SigFlow 生成 UI receipt。
4. UCAgent 验证并消费 receipt 后才显示参考解法。
5. 重复点击同一 action 不会重复解锁或推进状态。

### 4.11 35:00–39:30｜nextpnr、Pack 与人工烧录

切换到 `demo-fixed` 或修复后的当前工程。

操作顺序：

1. 打开 nextpnr 页，启动 Place and Route。
2. 展示输入来自成功的综合网表，CST 已通过校验。
3. 展示 pack/place/route 阶段进度。
4. 打开 PnR 报告，突出 LUT、DFF、BSRAM、最高频率和 Warning。
5. 展示 PnR Job 历史、报告、日志、Retry/Cancel。
6. 切换 openFPGALoader 页，点击 Build `.fs`。
7. 展示 `.fs` 路径、Pack manifest、输入/输出 SHA-256。
8. 点击 Program Board，停在人工确认框上解释安全边界。
9. 确认后切换板卡机位，展示下载完成和 LED 行为。

旁白重点：教育 Agent 不能绕过 UI 自动烧录；真实硬件状态改变必须由用户确认。

### 4.12 39:30–46:00｜TraceBridge 硬件调试闭环

操作顺序：

1. 打开 Debug Contract 配置界面。
2. 展示探针路径、位宽、采样时钟、深度、预触发、协议和波特率。
3. 展示触发选项：立即触发、掩码相等 N 次、停滞、握手超时、上升沿、下降沿；只选用已经验收的单时钟模式。
4. 保存 Contract，打开 TraceBridge Hardware Capture。
5. 展示七步条：契约、构建、指纹、配置、Arm、采集、波形。
6. 选择串口和协议，点击“构建、下载并采集”。
7. 在确认框停留，随后确认。
8. 展示 Overlay 构建说明：用户 RTL 源文件未被修改，调试 Wrapper 和 ILA 进入独立会话目录。
9. 展示实时进度和结构化日志；捕获完成后自动打开 HW VCD。
10. 展示历史会话、导出和导入。
11. 选择仿真 VCD，打开“双轨波形”。
12. 同步缩放和播放头，切换到“比对结果”。
13. 展示对齐锚点、首差异信号、期望值、实际值和置信度。
14. 双击差异事件，跳回波形时间点、SFTree/画布对象和 RTL 行。
15. 点击“生成重放 VCD”，说明可把硬件输入/行为带回仿真复现。

建议准备一次故障分支的短插段：

- Contract 与旧位流指纹不一致时拒绝采集；
- 串口断开或超时后显示清楚错误；
- 取消采集后不会留下伪成功会话。

### 4.13 46:00–49:00｜教育版 Agent 的工程边界与降级

操作顺序：

1. 展示 Agent 能力卡：`eda.sim.build`、`eda.sim.run`、`eda.synth` 可用。
2. 展示 `eda.pnr/pack/flash/debug` 为 disabled，并说明原因。
3. 演示一个最多三步的验证计划，失败后停止后续步骤。
4. 展示取消操作只影响当前 run/job。
5. 断开模型网络或关闭 sidecar，显示 Agent 不可用/规则模式。
6. 继续编辑、仿真或手动综合，证明 IDE 主流程不依赖 Agent。
7. 恢复 sidecar 后，通过 state/events 恢复状态，不重复提交 Job。

如果原生 Agent UI 尚未完成，改用技术附录中的 API 请求和状态图，不录制伪造的产品面板。

### 4.14 49:00–51:30｜插件化、可追溯性和跨平台证据

操作顺序：

1. 展示插件能力列表：Yosys、nextpnr、Gowin Pack、openFPGALoader、Verilator、Tang Nano 9K、Gowin CST、VCD、基础元件库。
2. 展示默认 Backend 可持久化选择。
3. 展示一次 Job 的 manifest、工具版本、输入 fingerprint、artifact hash。
4. 快速展示 Gateway 只监听 `127.0.0.1`、token 身份分类和路径不出工程边界。
5. 展示同一个 `Idempotency-Key` 重放返回同一 Job，而不重复消耗 grant。
6. 展示 Windows/Linux/麒麟同版本构建和测试结果表；只列实际验收的平台和架构。

这一章控制在三分钟内，画面以高亮字段和图示为主。

### 4.15 51:30–52:00｜收尾

画面回到四联屏：RTL、结构图、仿真/硬件波形、教学卡片。

旁白建议：

> SigFlow 教育版把学生的每一次设计、运行和修复都连接到可追溯证据。Agent 不替学生完成作业，而是帮助学生看懂真实工具结果、形成假设、亲手修改并用新版本重新验证。

最后显示项目名称、版本、目标板和演示日期。

## 7. 录制执行策略

### 7.1 分段录制

不要尝试一次录完。建议拆成以下素材包：

1. `A01_opening`：高光镜头。
2. `A02_project_editor_canvas`：工程、编辑、SFTree、画布。
3. `A03_sim_wave`：仿真和波形。
4. `A04_synth_pnr_pack`：FPGA 工具链。
5. `A05_board_program`：烧录和板卡近景。
6. `A06_tracebridge`：调试闭环。
7. `A07_agent`：教育 Agent 六条旅程。
8. `A08_backend_platform`：插件、Gateway、跨平台、测试。
9. `A09_failover`：错误和降级备用镜头。

每个素材包开头拍 2 秒静止画面，结尾再留 2 秒，方便剪辑。

### 7.2 工具运行等待

- 保留点击、开始状态和最终状态。
- 中间等待超过 8 秒时做 4×–12× 加速，并在角落标注“已加速”。
- 不直接跳过 Job ID 和状态迁移，否则观众无法确认是真实运行。
- 实时运行失败时，可切换到预生成 Job，但画面应说明“打开同版本预生成结果”。
- 不拼接不同 revision 的报告和源码冒充同一次运行。

### 7.3 旁白语言

每章遵循同一结构：

1. 用户现在要解决什么问题；
2. SigFlow 做了什么；
3. 产生了什么证据；
4. 这个结果能说明什么，不能说明什么。

避免使用“AI 自动保证正确”“一键解决所有问题”“支持所有 FPGA”等绝对表达。
